# 三生石 · 记忆 RAG 协议（2026-10-28 建立）

> 用阴间神话给记忆机制命名，是为了让每次会话都记得住这套流程。

## 一、概念对照

| 神话意象 | 技术概念 | 在本项目中的实体 |
|---|---|---|
| 孟婆汤 | 上下文清零 | 新会话开始，上一轮全部忘掉 |
| 脑容量 | 上下文窗口 | 一次能读进来的字数有上限 |
| **三生石** | **向量数据库** | `/data/workspace/三生石/` |
| 刻痕 | Embedding | `tfidf_X.npz`(稠密) + `bm25.pkl`(稀疏) |
| **招魂** | **RAG 检索** | `python3 三生石.py 召回 "查询"` |
| Top-K | 召回条数 | 默认 8，`-k` 可调 |
| 招错魂 | 检索按相似不按对错 | **最大风险，见第五节** |

## 二、目录结构

```
/data/workspace/三生石/
  chunks.json     604 个记忆块（石头本体，含来源/标题/行号）
  tfidf_X.npz     稠密向量矩阵（char_wb 2-4gram TFIDF）
  tfidf.pkl       TFIDF 模型
  bm25.pkl        BM25 统计量（jieba 分词）
  核心层.md       19KB 常驻铁律（孟婆汤解药）
  新刻石.md       新记忆待整理区
  chunk.py        切片器
  index.py        建索引
  core.py         抽核心层
  三生石.py       CLI（召回/开场/状态/刻/重建）
```

索引规模：604 块 / 31.2 万字符 / 均长 516 字，索引文件共 3.8MB，重建 2.2 秒。

## 三、命令

```bash
python3 三生石.py 状态                    # 看石头上有多少刻痕
python3 三生石.py 开场 "本次任务描述"      # 核心层 + 相关召回（新会话第一条命令）
python3 三生石.py 召回 "查询" -k 6        # 招魂
python3 三生石.py 召回 "查询" --tag MEMORY  # 只看 MEMORY.md
python3 三生石.py 召回 "查询" --full      # 不截断
python3 三生石.py 刻 "内容" --title "标题" # 刻新记忆 -> 新刻石.md
python3 三生石.py 重建                    # 改了源文档后重建索引
```

## 四、跨会话工作流（新会话固定动作）

1. **先喝孟婆汤**：承认上一轮全忘了，不要凭"我记得"回答
2. **喝解药**：`开场` 读核心层（27 条 ⛔ 铁律，5 千 token，不可跳过）
3. **招魂**：针对当前任务描述召回 top-6，**不要全量读 MEMORY.md**
4. **只对召回内容作答**；需要更多时换措辞再招一次

**关键：禁止用"我记得"代替检索。** 本项目血泪教训三条（bit 有无 ror、
math 有无 tanh、Data.Table 签名）全部源于凭记忆下结论，且恰好记反。

## 五、招错魂（最大风险）与对策

石头按**距离**找，不按**对错**找。问报销可能捞回离职记忆，还答得很流利。

对策四条：
1. **核心层常驻**：⛔ 铁律不走检索，避免被"没召回到"而违反
2. **结果带来源**：每条显示 `文件名 · 标题 · 行号`，可回原文核对
3. **交叉验证**：关键结论用两种措辞各招一次，看是否召回同一块
4. **冲突时以真机实测为准**：检索结果与用户实机反馈冲突 → 听用户的

## 六、维护

- 源文档改动后 → `重建`（切片 + 建索引，2 秒）
- 新结论 → `刻` 进新刻石.md → 定期并入 MEMORY.md → `重建`
- 核心层由 `core.py` 从 MEMORY.md 自动抽（标题含 ⛔/★★/铁律/红线/纪律/废除）

## 七、为什么不用真 Embedding 模型

沙盒装不上 `sentence-transformers`（pip 报 File too large），且无在线 API key。
现用**双路混合检索**，效果已验证够用：
- 稠密：字符 2-4gram TFIDF 余弦（中文无需分词，能容错字）
- 稀疏：jieba 分词 BM25（能抓准术语）
- 融合：**RRF**（`Σ 1/(60+rank)`）+ 标题命中加成

实测 4 条铁律类查询，目标块全部进入 top-3。

## 引擎元数据铁律（踩过多次）

`propertys` / `openFunctions` / `openFnArgs` 都是引擎在**加载期**读的元数据：
- **绝不能搬进 OnStart** —— 否则属性面板空白、属性全丢、二维表 ID 读不到。
  「非函数字段放 OnStart」只是规范 WARN，**永远不要为满足它牺牲功能**。
- **元方法（`__index` 等）不能改名**，改名会让数组返回值失效。
- 开放函数名改名时**登记表键必须同步改**，否则触发器看得到函数但调用返回 nil。
- 生命周期 `OnStart`/`OnDestroy`/`OnUpdate` **永不改名**（引擎按名字调用）。
- 元数据里的字符串**不要用 `_DEC()` 加密** —— 引擎在受限环境求值，
  看不见 chunk 顶层 local。用 `string.char(...)`（纯全局，可达）。

### ⛔⛔ Data.Map 作用域语义（2026-10-18 用户确认，权威）
- **`playerId = nil` → 房间级**（同一存档的房间内共享）
- **`playerId = 数值 uin` → 私人级**（该玩家跨房间/跨存档可见）
- 没有"全服级"这一档：全服要靠**共享同一个 varId + 房间级 nil** 来实现，
  **跨房间共享同一个 varId = 真**（已确认）。
- 因此：**留空 = 房间共享，填 uin = 私人**；选错空间 = 数据互相看不见，**不报错**。
- **同一空间必须用同一个 pid 值建实例**：`FSGET(vid,nil)` 与 `FSGET(vid,0)` 会建出
  **两份实例、两套缓存**，同空间两份副本互不可见（KVFS v2 的 Hash/SimFind 恒 -404 根因）。
  修法：`PIDOF()` 把 `0 / "" / "0"` 一律归一为 `nil`；**uin 保持原样不归并**。
- **一个脚本里所有 KV 调用必须走同一个 pid**，不能某个函数写死 nil、其余用 playerId。

推论：
- 存二进制/压缩数据 → 选 **Data.Map / Data.Array**，**不要套 base85**（省 25% 体积 + 编解码 CPU）。
- 二维表路径上值的"可打印"是硬约束 → **base85 仍是正解**。
- Data.Map 的 Key 建议用 **base85 哈希**：字符集 `33 + 35~117 + 126` **不含空格(32)**，
  32 字节哈希 → 约 40 字符 < 50 字节，安全。
- 2MB value ≠ 一次写 2MB：KV 限流 `30 + n×10` 次/分，单次塞满易超时；实践单次几十 KB + 分片。
- 导出的表若要导入别存档 → 按**导入侧** 500KB + 2000 行 设计。

## ★★ Data.Map:UpdateValueAndCallback = 服务端原子 RMW（2026-10-18 官方文档实证）

3. SET 与 OK 可能同值（官方博客"首次调用 ret 必然为 0"），
   必须用"值==刚返回的新值"或调用序号兜底
4. 重试耗尽 → 直接 set 最后合并结果仍是安全的（join 保证已见内容都在里面）

- 全图共享配额 `30 + 在线×10` 次/分 → 人均预算 ≈ 10 次/分

## ⛔ 教训：长字符串闭合写反会吞掉整段（2026-10-20）

## ⛔⛔ Lua 5.1 unpack 遇到 nil 空洞会截断参数（2026-10-22 实踩）

```lua
unpack({ 90001, nil, "xsKey" })   -- #{90001,nil,"xsKey"} 是未定义行为
-- 实际可能只传 1 个参数，后面的静默丢失
```

**杀伤点**：KV 调用里"房间级"的 `playerId` 恰好就是 nil → 用 unpack 拼参数，
`SetValue(varId, nil, key, val)` 实际只传了 varId → **写了个空键，返回 true，假成功**。
表现：写 OK、读为空，**不报错**。

**规则**：变体/可选参数一律写成**闭包显式传参**，绝不用 unpack：
```lua
{ function() return pcall(f, m, vid, pid, key) end,   -- 显式传 nil 安全
  function() return pcall(f, m, vid, key) end }
```

## ⛔ 旧"跨存档传递"办法 = 字符串共享元表侧信道（已废）

`跨存档信息传递.lua` / `跨存档JSON.lua` 用的是：

### ⛔ 审计规则本身的坑（我第一轮误报 241 条）

# 逐 token 流式输出到 CustomUI 元件（实测结论）

## 已确认失败：coroutine + ThreadWait
现象：要么完全不回答，要么卡一下只吐出一个字。
根因：`coroutine.create` 出来的协程里调用 `self:ThreadWait(秒)` 挂起后，
**引擎不会 resume 这个协程**，它死在第一个 yield 处。
结论：**ThreadWait 只对「事件回调本体」有效，对自建 coroutine 无效。**

## 可用方案：计时器事件驱动泵（照抄《计时器管理2代》）
```
OnStart:  self:AddTriggerEvent(TriggerEvent.MinitimerChange, Script.OnPumpTick)
StreamAsk: 建状态 -> Timer:CreateTimer(name) + Timer:StartForwardTimer(h, sec, true)
           -> 推首帧(thinkText) -> 立即 return
OnPumpTick: 每次只推进一小步(prefill 若干 token / 生成若干 token)
           -> CustomUI:SetText -> return
关键：脚本 return 即引擎 flush，UI 才会真刷新。
```

## 计时器 API（来自计时器管理2代）
- `Timer:CreateTimer(名字)` -> handle；名字用数字字符串
- `Timer:StartForwardTimer(handle, 秒, 是否循环)` / `StartBackwardTimer`
- `Timer:DeleteTimer(名字或handle)`
- 事件参数：`e.timername` / `e.timertime`

## SetText 签名
`CustomUI:SetText(玩家ID, 界面ID, 元件ID, 文本)`（4参）实测命中。
界面ID 由元件ID 派生：去掉末尾 `_N`，如
`7695242090665913341-110874_1` -> `7695242090665913341-110874`。

## 参数
- `streamTickSec`(1)：泵 tick 间隔；引擎最小颗粒常为 1 秒
- `streamPerTick`(1)：每 tick 生成几个 token；26M 模型约 0.4s/token，
  设 1 最顺滑（每 tick 只阻塞约 0.4s）
- `prefillChunk`(8)：prefill 也按 tick 摊开
- `streamEventId`：生成结束时 `PushCustomEvent(ID, 完整文本)`（借鉴计时器实时广播）
- `streamFormat`：含 %s 的显示格式串（借鉴 BindUIToTimer 的 binding.format）

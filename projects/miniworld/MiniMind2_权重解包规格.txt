  70 张 CSV (磁盘 32 MB)

     v
  32,841,780 个 base85 可打印字符   <- 含 305,413 处 ~q 转义
     |
     | ~q -> "   （必须整串做！有 1 处 ~q 被切在两张表之间）
     v
  32,536,367 个字符
     |
     | base85 解码（5 字符 -> 4 字节，末组补 u）
     v
  26,029,093 字节 = 24.82 MiB      <- 膨胀率 1.262

膨胀率 1.262：1 个字节占 1.26 个可打印字符。
用 base85 而非 base64 的原因：KV 表 value 只认那 94 个符号，
而 base85 只用 33~117 这一段，正好落在里面。

[*] 坑：~q 还原必须对整个拼接串做，不能逐表做。
    实测有 1 处 ~q 正好被切在两张表之间，逐表还原会漏掉它，
    剩下的 ~(126) 超出 base85 字符集，BV[126] 是 nil，解码当场崩。

4. 单矩阵格式 (readMat)
------------------------------------------------------------

  [ f32 scale x rows ]  [ uint8 (w+128) x rows*cols ]

  - 权重 int8 量化，存的是 w+128 的无符号字节
  - 反量化：w = (byte - 128) * scale
  - 每行一个 f32 scale（不是每通道、不是每张量）
  - 实测 scale 范围 0.000349 ~ 0.007675，中位 0.001428，全为正
  - 字节取值 256 种全部用到，还原后均值 0.327

  由此得到 matvec 能成立的数学依据：

    sum( w[j]*x[j] ) = sum( (b[j]-128)*x[j] )
                     = sum( b[j]*x[j] ) - 128 * sum(x[j])

  直接拿 string.byte 的原始值相乘，行末减一次 128*sumX 即可，
  省掉 2900 万次查表。

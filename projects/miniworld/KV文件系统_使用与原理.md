# 迷你世界 KV 表文件系统 · 使用手册与原理说明

> 版本：v3（云服版 / 房间个人版）
> 适用：迷你世界 UGC 3.0 脚本组件（Lua 5.1）
> 依赖：`bit`（位运算）、`json`（序列化）——引擎内置，探针已实测存在

---

## 一、它是什么

把迷你世界的 KV 表当成一块「硬盘」，在上面实现一套完整的 POSIX 风格文件系统：

- 目录树、绝对路径 / 相对路径、通配符与内容检索
- 大文件自动分片（单文件可超过单条 value 上限）
- 文件夹打包成单文件、跨 KV 表迁移
- 属主 / 权限位、对称加密、RSA 混合加密
- 相同判定（MD5）、相似检索（SimHash）
- 云服版额外带限流令牌桶与写入队列

**两套脚本的分工**：

| | 云服版 | 房间/个人版 |
|---|---|---|
| 底层接口 | `Data.Map:*ValueAndBlock`（阻塞） | 适配器：优先阻塞系列，回退 `Trigger.KvMap` |
| 限流 | **有**，必须排队 | 无限制，直读直写 |
| 隔离键 | `varId\|playerId` | `varId\|playerId\|scope` |
| 专属函数 | `SetOnline` / `SetQuota` | `SetScope` / `SetCache` |

## 二、导入与配置

### 2.1 导入

新建一个**脚本组件**，把 `KV文件系统_云服版v3.lua` 或 `KV文件系统_房间个人版v3.lua` 整段粘进去保存。**两套不要同时塞进一个组件**（都定义了 `Script`，会互相覆盖）。

### 2.2 组件属性

**云服版**

| 属性 | 默认 | 含义 |
|---|---|---|
| `shardSize` | 1048576 | 分片大小（字节），范围 65536–1900000 |
| `indexOn` | 0 | 路径索引开关 |
| `qBase` | 30 | 限流基数（次/分） |
| `qPerPlayer` | 10 | 每人增量（次/分） |
| `online` | 1 | 在线人数估算 |

**房间/个人版**

| 属性 | 默认 | 含义 |
|---|---|---|
| `shardSize` | 1048576 | 同上 |
| `indexOn` | 1 | 路径索引（建议开） |
| `safeMode` | 0 | 分片 Base94 编码（保守模式下开） |
| `useCache` | 1 | 读缓存 |

### 2.3 第一次使用

```
Init(变量ID, 玩家)        -- 建根，返回 root id
Mkdir(变量ID, 玩家, "/docs")
MkFile(变量ID, 玩家, "/docs/a.txt", "内容")
Read(变量ID, 玩家, "/docs/a.txt")
```

`玩家` 传 `0` 或空表示公共空间；传具体 playerId 即个人空间。

## 三、双返回模式（重要）

每个开放函数**最后一个参数**都是「广播消息ID」：

- **不填 / 填 0 / 空串** → 函数返回值就是完整结果（**确定性返回**，触发器可直接用）
- **填了**（查询类）→ 返回值照给，**同时**把结果推到该消息ID
- **填了**（变更类）→ 只返回回执 `{async:1, evt:"..."}`，完整结果走广播

```lua
-- 确定性
local r = Script:Read("v123", 0, "/a.txt")

-- 实时/延迟通道
Script:Read("v123", 0, "/a.txt", "EVT_READ")
-- → 返回 {"code":0,"async":1,"evt":"EVT_READ"}
-- → 同时 PushCustomEvent("EVT_READ", 完整JSON)
```

这样既能被触发器直接消费，也能喂给 UI 元件做异步展示。

## 五、数据模型

### 5.1 Key 布局（严格遵守 50 字节上限）

Key 只使用你给出的 94 个可见符号，**不含空格**，实测最长 33 字节：

```
r<varId>              根节点指针
n<id>                 节点元数据（JSON）
k<id>_<page>          目录子项分页表
d<id>_<seq>           文件数据分片
i<md5hex>             内容索引（1+32=33 字节）
s<seg><hex2>          SimHash 分桶
```

**为什么索引必须用 MD5 而不是 SHA-256**：SHA-256 的 hex 是 64 字符，加前缀后 65 字节 > 50 上限，**放不进 key**。MD5 的 32 字符 + 1 前缀 = 33 字节，是唯一能塞进索引键的标准哈希。这是硬约束倒逼的选型，不是偏好。

### 5.2 目录：邻接表 + 子项分页

每个节点存 `parentId` 与 `children` 映射。子项过多时自动**分页存储**（`k<id>_<page>`），避免单条 value 膨胀——这就是"支持大批量"的落点：实测单目录 500 个子项正常读写，`List` 分页返回。

查询时按名字排序后分页装载，不做全量反序列化。

### 5.3 文件：压缩 → 分片 → 逻辑块

```
原始内容 → 哈夫曼压缩 → 按 shardSize 切物理分片 → 存 d<id>_<seq>
                ↓
         按 64KB 逻辑块算 Merkle
```

**关键设计**：逻辑块（64KB）与物理分片（默认 1MB）**解耦**。所以改 `shardSize` 不影响指纹，跨表迁移后 MD5 仍然一致。

## 六、各项功能的原理

### 6.1 相同判定：MD5 + Merkle 树

- 内容 ≤ 64KB → 直接 `MD5(content)`
- 内容 > 64KB → 按 64KB 切块，做两级 Merkle：`root = MD5(h1‖h2‖...)`

**Merkle 的价值**：改一个块只需重算该块及其到根的路径，不必重算全文件。代价是 **Merkle 根 ≠ 整包 MD5**——这是分块增量哈希的固有取舍（实测 70KB 文件 `hm=merkle`，根值 `bc0f1929...`，与整包 MD5 不同），但**同内容必然同根**，去重判定完全够用。

> 注意：MD5 已不适用于安全场景（碰撞攻击），此处只用于**内容标识**，不用于防篡改。防篡改靠 6.6 的 MAC。

### 6.2 相似判定：SimHash + 鸽巢分桶

SimHash 把内容映射成 32 位指纹，**相似内容的汉明距离小**。

检索加速用**鸽巢原理**：把 32 位切成 4 段 × 8 位建桶。若两个指纹汉明距离 ≤3，则 4 段中**至少有一段完全相同**（否则至少 4 位不同）。所以只需查 4 个桶的并集，无需全表扫描。实测 300 组随机样本 0 漏检。

目录的 SimHash 由子节点**按位投票合并**（权重含 size），因此文件和目录共用同一套相似语义。

> SimHash 是概率性的，只适合**召回候选**；唯一性判定必须交给 MD5。实测出现过目录与文件距离为 0 的情况。

### 6.3 大批量与分片

物理分片默认 1MB，value 上限 200 万字节，因此单文件理论可达 **分片数 × 1MB**，只受配额总量约束。实测 16000 字节 / 4096 分片 → 2 个分片（哈夫曼后 6020 字节），往返一致。

分片支持**比特流**：`\0 \1 \255 \127` 全部无损往返（实测通过）。

### 6.4 压缩

哈夫曼编码，`COMP_MIN=384`（小于此不压，避免负收益）。实测 16000 字节重复内容压到 6020 字节。

### 6.5 权限

Unix 九位模式（`owner/group/other × rwx`），`owner=0` 视为 root 恒通过。

**重要**：权限是**逐节点**的，不继承（与 Unix 一致）。给目录 `chmod 0600` **不会**限制其下文件——要限制得对每个文件改。实测对文件 `/after.txt` 设 0600 后，非属主读被拒（`{"code":-2,"msg":"无读权限"}`），属主可读。

### 6.6 加密

**对称**：CTR 模式流密钥 `KS = SHA256(ek ‖ ":" ‖ ctr)`，32 字节一块做 XOR；然后 **Encrypt-then-MAC**：`tag = SHA256(mk ‖ ct)`，解密前先验 tag。

这一条不能省：裸 XOR 流无认证，翻转一个 bit 明文就跟着变且无从察觉。

**非对称**：内容仍用对称密钥，对称密钥用 RSA 公钥封装（`WrapKey` 传 e/n 的 hex）。即 KEM-DEM 混合结构——非对称只用来搬运短密钥，不用来加密大内容。

### 6.7 云服限流（云服版核心）

云服 KV 是**阻塞接口 + 配额限制**（约 `30 + 在线人数×10` 次/分，读写共享）。

**令牌桶**：按 `varId|playerId` 独立建桶，`tok` 按时间匀速补充，上限=配额。

**写入**：令牌不足时**入队而非丢弃**，之后用 `Flush` 补写。实测配额设为 2/分连续写 10 个文件 → `queued=12`，恢复配额后 `Flush` 全部刷出，`queued=0`。

**读取（v3 关键修复）**：读被限流时**绝不静默返回 nil**。因为核心把 `nil` 一律当作"键不存在"，静默 nil 会导致分片缺失、节点丢失等**无声数据损坏**。现在改为抛出并在统一边界返回：

```json
{"code":-429,"msg":"云服限流:操作已中止,结果不完整(可能有部分残留)",
 "queued":12,"hint":"调大 qBase / qPerPlayer 或用 Flush 刷写队列后重试;残留用 Find/Remove 清理"}
```

失败即整体失败并如实上报，绝不给调用方一份残缺数据。

### 6.8 打包格式

```
KVPK1\n  + [8位hex 相对路径长][路径][8位hex 元数据长][元数据][16位hex 内容长][内容] ...
KVPZ1\n  + 哈夫曼压缩后的同上载荷
```

**只压载荷、不压 magic 头**——否则解包时会少剥一层（这是开发中实测踩到的坑）。

### 6.9 跨表迁移

`Upload` 按节点遍历，源表读出、目标表写入，重建 id 映射。指纹在迁移后保持一致（逻辑块与物理分片解耦的收益）。

## 七、参数调优

| 场景 | 建议 |
|---|---|
| 云服写入频繁被限流 | 调大 `qBase` / `qPerPlayer`，或定时调 `Flush` |
| 大文件多 | 调大 `shardSize`（最高 1900000） |
| 房间表、内容不大 | `shardSize` 可降到 65536 减少浪费 |
| 目录子项极多 | `indexOn=1` |
| 只在乎省空间 | 保持哈夫曼开启（默认开） |
| 云服卡顿 | 降低单次操作规模，改成分批 + `Flush` |

## 九、已知边界（如实说明）

1. **Merkle 根 ≠ 整包 MD5**，跨算法（与其他系统的 MD5）不可比。
2. **SimHash 概率性**，只用于召回，不用于判定。
3. **权限不继承**，逐节点设置。
4. **云服多步操作中断可能残留**：v3 已保证会明确报 -429 而不是静默损坏，但**没有实现崩溃后的日志重放**，残留需 `Find` + `Remove` 手工清理。
5. **大文件不计算全量校验值**（>64KB 走 Merkle，不额外算整包 MD5），纯 Lua 哈希超过约 256KB 会明显变慢。
6. **随机源是 `math.random`**，非密码学安全。游戏场景够用，不要用于保护真实资产。
7. **`Pack` 返回的是裸包串（含二进制）**，若通过 `PushCustomEvent` 广播，需确认事件负载能承载二进制；否则用返回值直接传递。
8. **云服版 `Flush` 每次调用只按当前可用令牌刷写**：配额很低时需要多次调用或先调大配额。

## 十一、快速排错

| 现象 | 原因与处理 |
|---|---|
| `GetMapValue` nil | 旧版接口名，v3 已改用 `GetValueAndBlock`；确认用的是 v3 |
| 返回 `{"code":-429}` | 云服限流，调大 `qBase` 或 `Flush` 后重试 |
| `路径不存在` | 先 `Init`；路径需以 `/` 开头或相对起始路径 |
| 权限没生效 | 权限不继承，需对目标文件本身 `Chmod` |
| 加密后读不出 | 需 `Unlock` 传正确口令 |
| 找不到重复 | 先 `Reindex` 重建分桶 |

## 12. v3 修订记录（真实测试暴露的缺陷，均已修复）

### 12.1 `**` 通配符会命中全部文件（最严重）
`Find("f25*")` 实测返回 500 条。原因：单段模式（如 `f25*`）按 `find . -name` 语义自动展开为
`{"**","f25*"}`；而 `**` 分支在"其后仍有模式段"时，**无条件把本层全部文件收录**，
下一段模式 `f25*` 根本没有参与本层判定。

修复：`**` 可匹配**零段**，因此其后还有模式时，本层文件应交给下一段模式判定
（`wild(pats[depth+1], nm)`），只有 `**` 为最后一段时才递归全子树收录。
修后 `f25*` → 11 项（`f25`、`f250`–`f259`），`**` 全量 → 505 项，两者均正确。

### 12.2 `Find` 的 limit 未严格生效
原匹配循环内没有 limit 检查，只有函数入口查一次，故 `Find("*.txt", 10)` 返回 300。
已在循环内加截断，现严格返回 10 项。

### 12.3 云服读被限流时静默返回 nil（会造成无声数据损坏）
原云服适配器 `get()` 在令牌耗尽时返回 `nil`，而上层**一律把 nil 当作"键不存在"**。
后果：分片缺失、节点丢失，且**没有任何报错**——这是最难排查的一类故障。

修复：适配器限流时返回显式信号 `"RATE"`，`FS:get` 收到后抛出带标记的错误，
开放函数层统一 `pcall` 捕获，翻译为：

```json
{"code":-429,"msg":"云服限流:操作已中止,结果不完整(可能有部分残留)",
 "hint":"稍后重试;已写入分片可能残留,建议 Find+Remove 清理","queued":12}
```

> 顺带修正一处不准确的表述：原话术称"未落任何数据"是错的——中止前同一操作内的
> 写入其实已经落盘，可能有残留。新话术已如实说明。

# 拼音输入法 v4 · 二维表满利用率版

迷你世界 UGC 3.0 组件脚本。词库全部存在二维表里，运行时按需解压。

## 相比旧版的改进

| 项目 | 旧版 | v4 |
|---|---|---|
| 二维表数量 | 19 张 | **15 张**（省 4 张） |
| 每表利用率 | ~92% | **99.6%**（实测 498.2KB / 上限 500KB） |
| 每行载荷 | 变长 | **2000 字符**固定 |
| CSV 转义 | 有（`"` `\` 需转义，占 1.17%） | **零转义**（新 base85 字符集排除 `"` `\` `,` `|`） |
| 段存放 | 必须连续 | **可任意分散**在任意表（每行带段号，装箱才能拉满） |
| 功能 | 仅精确查询 | Query / Prefix / Abbr / Sentence / Warm / Status |

## 部署步骤

1. **导入 CSV**：把 `csv/py4_01.csv` ~ `py4_15.csv` 逐个导入二维表（共 15 张）
2. **复制 ID**：每张表导入后有一个 ID（形如 `v769...`）
3. **填属性**：把 15 个 ID 用逗号分隔填进组件属性 `二维表ID组`
4. **导入脚本**：`拼音输入法v4.lua` 作为组件导入
5. **验证**：触发器调 `Status()`，正常应显示 `表数=15 | 段数=916 | 已扫到段号=917 | 字典ok | ni=你`

⚠️ ID 顺序无所谓（每行自带段号），但**一张都不能少**，少一张对应的段就查不到。

## 开放函数

| 函数 | 参数 | 说明 |
|---|---|---|
| `Query` | 拼音, 最多几个 | 精确查候选词，按词频排序 |
| `Prefix` | 拼音前缀, 最多几个 | 前缀联想，返回所有以该串开头的拼音的候选 |
| `Abbr` | 首字母串, 最多几个 | 简拼查词（如 `nh` → 你好） |
| `Sentence` | 连续拼音, 每音几个 | 整句拼音转汉字，贪心最长成词 |
| `Warm` | 桶名 | 预热某个桶的全部块（首次查询前调用可提速） |
| `Status` | — | 诊断：表数、段数、字典状态、自检 |

## 技术细节

**编码链**：汉字变长编码（高频 128 字 1 字节、其余 2 字节）→ deflate(level 9) → Base85

**段格式**：每行 `C|段号|载荷分片`，段可跨表存放

**段类型**：
- `@MANIFEST`（段号 0）全部段名清单，用于检测缺表
- `@D<n>` / `@A<n>` 字典 / 符号表（存原文，按长度截断）
- `@S` 音节表（411 个合法音节，整句切分用）
- `@K<桶>#<块号>` 拼音块（key=value，用 `\1` 分隔）
- `@I<桶>` 块首 key 索引（查询时先读它定位块，只解压那一块）
- `@F<首字母>` 简拼表分片

**模糊音**（属性 `启用模糊音` 控制，默认开）：zh↔z、ch↔c、sh↔s、ing↔in、eng↔en、ang↔an、n↔l、r↔l、f↔h

## 已知限制

- `Sentence` 是贪心最长匹配，**没有语言模型**，长句可能切错（如歧义音节边界）
- 首次查询某桶需要解压该块，纯 Lua inflate 有开销；高频桶建议先 `Warm`
- 段缓存上限 40 个，超出按插入顺序淘汰

## 数据规模

- 163 个拼音桶、84233 条简拼、411 个音节
- 15 张表、917 个段、总载荷 7.21MB（base85 后）

# 音效与 TTS 调度

> 更新：2026-10-15（第三轮：1356 音节体系 + 广播自驱动泵）
> 状态标注：【已测】= 实测确认　【未测】= 待验证
> **基准：Lua 官方 5.1｜`os.timeMs` 可用，`os.clock` 不存在**

## 一、时间铁律：os.timeMs（毫秒）

```
os.timeMs()    ✅ 存在，返回毫秒整数
os.clock       ❌ 不存在，用了必崩
os.date        ✅
os.time        ✅
```

**凡是按时间推进的调度，一律用 `os.timeMs` 绝对时间戳，绝不用"每帧累加固定步长"模拟时间。**

### 反面案例（v3.1 只播 1 个音节的根因）

```lua
local step = self.tickMs or 50
_elapsed = _elapsed + step        -- 名义前进 50ms
```

`ni2` 时长 576ms，减尾部裁剪 30 → 第二个 `hao3` 的 `at = 546ms`。
`_elapsed` 每次只 +50，需要 **11 次 Tick**。
若循环触发器实际 1 秒一次 → **真实要等 11 秒**，用户以为只播了一个。

| | 第 2 个音节播出时机（Tick 实际 1 秒一次） |
|---|---|
| 名义步长累加（v2/v3.1） | 第 **11** 次 Tick，真实 **11000ms** |
| `os.timeMs` 绝对基准（v3.2） | 第 **1** 次 Tick，真实 **1000ms** |

### 暂停必须冻结时间轴（易写错）

```
Pause:   _frozenMs = os.timeMs()
Resume:  _baseMs = _baseMs + (now - _frozenMs)   -- 把暂停时长扣掉
```

实测：暂停时时间轴冻结在 200ms，期间真实过了 5000ms；恢复后仍是 **200ms**，不是 5200ms。

## 二、三个音效 API

| API | 说明 |
|---|---|
| `PlaySoundEffectOnPos(uin, soundId, x, y, z, volume, pitch)` | 播放 |
| `StopSoundEffectOnPos(uin, soundId, x, y, z)` | 停止，`soundId = -1` 停该位置所有 |
| `PauseSoundEffectOnPos(uin, soundId, x, y, z)` | 暂停 |

### ⚠️ 字符串 ID 无法精确定位暂停

`PauseSoundEffectOnPos` 的 `soundId` 是 **number**，自定义 ID 是字符串 `s_***`，**传不进去**。
脚本只能退用 `-1` → **副作用：该位置的其他音效也会被一起暂停**。

这是 API 本身的限制，不是没处理好。设计上要避免同一坐标同时播多个需要独立控制的音效。

## 三、广播自驱动泵（v3.2，照抄 MiniMind2 v24 模式）

**根因**：v3.1 的推进全靠"外部循环触发器调 Tick"。用户没配（或配的不是循环）→ 第二个音节永远没人播 → **返回 2、播 1**。

**解法**：脚本自驱动。

```lua
self:AddCustomEvent(广播ID, fn)      -- 收
self:PushCustomEvent(广播ID, ...)    -- 发
```

`Say` 播完首音节 → 发一条广播 → 引擎回调 → 按 `os.timeMs` 播到期音节 →
队列没完再发一条 → 循环；播完即停。

> **广播只当心跳，时间节奏仍由 `os.timeMs` 决定** —— 所以广播不带延迟也没关系。

### 三套驱动（可并存，推进幂等）

| 驱动 | 精度 | 要配什么 |
|---|---|---|
| **广播自循环**（主） | 帧级 ~16ms | 属性填【驱动广播事件ID】 |
| 计时器泵（兜底） | 引擎最小 ~1 秒 | 自动注册，不用配 |
| 手动 Tick（兼容） | 取决于触发器 | 循环触发器 |

**配置只有两步**：触发器里新建一条广播消息拿到 ID → 填进属性。
不需要再配"循环调用 Tick"。

### 诊断

| 现象 | 原因 |
|---|---|
| `Drive()` 显示 `tx>0 rx==0` | 广播 ID 不对（必须是触发器里新建的那条，自己编字符串没人收） |
| 播 1 个就停 | 引擎是**同步广播**，递归被深度保护挡住 → `SetDrive(2)` 走计时器 |

## 四、1356 音节体系

### 索引构建

按**文件名升序**（a1 → zuo5），**1-based**，与 `音节索引对照表.csv` 一一对应。
索引表与时长表压成两个字符串常量内置（索引 7066 字符、时长 4068 字符），不用查表、不用解码。

### 音效数组格式（不要改）

```lua
-- 属性：Mini.Array(Mini.Sound)，按 1→1356 顺序添加
-- 位置即索引
```

音效 ID 带时间戳、**根本不连续** → `base + i - 1` 这种算法是错的，已删除，**只走数组点选**。

> 实测过的两种取法（A 数组 / B 起始ID），B 已被证伪，全文件 0 处残留。

### 时长表

1356 个 mp3 逐帧读帧头取真实时长：**312~696ms，平均 544ms**。
与《带调音节清单_1356.txt》集合比对 **零差异**。

### 尾部静音裁剪

每个音节尾部有 25~35ms 静音 → 默认裁 **30ms**，让下一个提前启动，连读更顺。

## 五、调度状态机

```
idle → playing → (paused) → playing → idle
                    ↓
                 stopped
```

五个动作：播 / 停 / 暂停 / 恢复 / 截断（`Truncate(n)` 丢弃后 n 个），另加 `Skip(n)`。

### 补播上限

久未调用时一次最多补播 **8 个**（`maxCatch`），防止憋久了全喷出来。

## 七、已知边界

- **`循环触发器`在 v3.2 已非必需**（自驱动），但广播 ID 必须配置正确
- **语调是死的** —— 声调固化在录音里，整句没有抑扬顿挫。这是拼接法天花板，不是 bug
- **英文/数字默认不朗读** —— `Syl` 原样保留。可开「数字读法」逐位读（2024 → 二零二四），但无十/百/千数位规则
- **mp3 接缝**：每帧 1152 样本 + 编码延迟（529~576 样本）。用户实测无咔哒声；若出现则转 WAV 零交叉点裁剪

# 二维表与编码规范

> 更新：2026-10-15（第三轮：真二维表格式 + base85 字符集 + 量化）
> 状态标注：【已测】= 实测确认　【未测】= 待验证
> **实测基准：沙盒内真在用的 `_mmbin/二维表CSV/mmlm_1.csv`**

## 一、真二维表的格式（必须严格照抄）

```
字段备注,权重数据,
字段名,权重数据,
字段类型,string,
1,"MMLM|",
2,"9he;U0`V7T!!iQ)!!3-#!'gMa!...",
```

| 要素 | 值 |
|---|---|
| 列数 | **3 列**：行号 / 引号包裹的值 / 空 |
| 元数据行 | **前 3 行**（字段备注、字段名、字段类型） |
| 值包裹 | **必须双引号** |
| 单表规模 | 945 行 × 500 字符 |

### ❌ 常见错误：逻辑名当首列

```
W1,16,33,0.0546,...      ← 裸浮点、变长列数、无引号
```

引擎按「行号 + 单值」导入，**这种它解析不出来**。
首列必须是行号（数字），不能是逻辑名。

## 二、字符集：85 个，引号被排除

对真实编码区做字符统计，正好 **85 个**：

```
33 (!) + 35~117 + 126 (~)          含 34 (") ?  False
```

| 要点 | 说明 |
|---|---|
| **34 `"` 被排除** | 引擎 value 不接受引号 → 所以需要 `~q` 转义 |
| **126 `~` 保留给转义** | 出现 `~` 说明后面是转义序列 |
| **44 `,` 在合法范围内** | ⚠️ 见下，这是最大的坑 |

## 三、⚠️ 逗号陷阱（最容易静默毁掉数据）

`ord(',') = 44`，**落在 35~117 内** → 逗号是 base85 的合法字符。

真实数据里就有这种：
```
),IkSQ
```

**所以绝不能用 `split(',')` 解析二维表**，必须靠**引号定位**取字段。

> 真二维表用引号包裹，正是为了隔离值内部的逗号。

### 错误实现（实测会错位）

```lua
for w in string.gmatch(line, "[^,]+") do ... end   -- ❌ 跳过空字段 + 被值内逗号击穿
```

`[^,]+` 还有第二个问题：**空字段会被跳过**（`"a,,b"` 得 2 个而非 3 个）。
负权重的 `-0`、科学计数法的 `1e-5` 一旦产生空串就全乱。

### 正确做法

按引号位置切分：
```lua
local a = string.find(line, '"')
local b = string.find(line, '"', a + 1)
local val = string.sub(line, a + 1, b - 1)
```

## 四、base85 编解码

### 膨胀率

```
1 字节 → 1.262 个可打印字符（5 字符编码 4 字节）
```

之所以用 base85 而不是 base64：KV 表 value 只认那 94 个可打印符号，
base85 只用 33~117 这一段，正好落在里面。

### ⚠️ 末组截断的借位 bug（隐蔽）

标准 Ascii85 末组不足 4 字节时补 `u`。但当**末位 digit = 84** 时会**借位破坏前一字节**：

```
0aaaf4  → 编码 %FF_  → 解码回 0aaaf3     ← 错 1
```

**解法**：编码前补零到 4 的倍数，**永不截断末组**。

### ~q 转义必须全局做

~q 还原必须**对整个拼接串做，不能逐表做**。

实测有 **1 处 `~q` 正好被切在两张表之间** → 逐表还原会漏掉它，
剩下的 `~`(126) 超出 base85 字符集，`BV[126]` 是 nil，**解码当场崩**。

## 五、权重量化：int8 + per-row f32 scale

### 二进制布局（单层单个矩阵）

```
[ f32 scale × rows ]  [ uint8 (w+128) × rows×cols ]
```

- 存的是 `w + 128` 的无符号字节
- 反量化：`w = (byte - 128) × scale`
- **每行一个 f32 scale**（不是每通道、不是每张量）

### 为什么能直接拿原始字节相乘

```
Σ w[j]·x[j] = Σ (b[j]-128)·x[j] = Σ b[j]·x[j] - 128·Σx[j]
```

直接 `string.byte` 取原始值相乘，**行末减一次 `128·sumX`** 即可 ——
省掉每元素一次查表（26M 模型即 2900 万次）。

### 量化损失实测

| 对比项 | 结果 |
|---|---|
| Lua vs Python 偏差 | **1.045e-06** |
| 分类一致 | **60/60** |
| 体积 | 15496 B → **1466 B（9.5%）** |

**神经网络不需要 double，工业标准本来就是 int8。**

## 六、MiniMind2-Small 的实测布局（参考）

```
magic MMLM1 (5 B)
配置头 u32×8 (32 B)      dim=512 nLayers=8 nHeads=8 nKvHeads=2
                          headDim=64 hidden=1408 vocab=6400 maxCtx=512
embed 3,303,400 B
层 0…7  22,749,952 B
fnorm   2,048 B
总计 26,029,093 B = 24.82 MiB
```

- **nHeads=8 但 nKvHeads=2** → GQA 分组查询注意力，KV cache 只要 1/4
- 总参数 **25,821,184 = 25.8M**
- FFN（w1/w2/w3）占 **67%**，embed 12.7%，注意力合计 20.3%
- 每层固定结构：`an(2048) → wq → wk → wv → wo → fn(2048) → w1 → w2 → w3`
- 归一化层（an/fn/fnorm）**不量化**，直接存 float32

### 70 张表的切分

前 69 张各 **944 行 × 500 字符**（约 374,000 字节/张），最后一张 548 行收尾。
按**字符数均匀切**，不是按语义边界 → 所以跨表的 `~q` 才会出现。

## 一、结论先行

| 事项 | 状态 |
|---|---|
| `CloudSever`（注意是 Sever 不是 Server） | **已废弃**，不要用 |
| 现行方案 A：组件脚本 | `Data.Map:*` 共 13 个函数（KV 表 + 排行榜统一接口） |

## 三、现行方案 A：`Data.Map` 模块（13 个函数）

**开启方式**：开发者工具 → 触发器 → **变量库 → 全局变量** → 选择「排行榜」或「表」

同一套函数同时操作 KV 表与排行榜，靠 `varId` 区分。

### 函数清单

| # | 函数 | 说明 |
|---|---|---|
| 1 | `SetValueAndCallBack(...)` | 回调方式设置 |
| 2 | `SetValueAndBlock(...)` | **阻塞**方式设置 |
| 3 | `RemoveValueAndCallBack(...)` | 回调删除指定 key |
| 4 | `RemoveValueAndBlock(...)` | 阻塞删除指定 key |
| 5 | `UpdateValueAndCallback(...)` | 更新指定 key |
| 6 | `GetValueAndCallBack(...)` | 回调获取 |
| 7 | `GetValueAndBlock(...)` | **阻塞**获取 |
| 8 | `GetIndexValueAndCallback(...)` | 取排行榜指定排名索引的值 |
| 9 | `GetIndexValueAndBlock(...)` | 同上（阻塞） |
| 10 | `GetNumValuesAndCallback(...)` | 取排行榜前 num 个值 |
| 11 | `GetRangeValuesAndCallback(...)` | 取排行榜值区间 min~max 的所有值 |
| 12 | `SetRankValueAndBlock(...)` | 阻塞设置排行榜值 |
| 13 | `ClearData(...)` | 清空 KV 表 / 排行榜 |

### 参数与返回值

**入参**
```
varId     : string  排行榜/表变量 ID（变量库里建的）
playerId  : number  玩家 uin（全局数据传 nil）
key       : string  键值（数值 key 会被转成字符串）
value     : string|number|boolean
callback  : function 内部回调（CallBack 版为必填，Block 版缺省）
```

**返回**
```
code        : number  ErrorCode（ErrorCode.OK / ErrorCode.KV_OP_NO_VAL …）
key         : string
value       : string|number|boolean
index       : 排行榜额外返回，排名
ascending   : 排行榜额外返回，是否升序
extendinfo  : 排行榜额外返回，扩展信息
```

⚠️ 排行榜的 `GetValue` **不一定**有 value 之后的参数，必须先判断。

### 示例

```lua
-- 写入（不支持直接存 table，需自行序列化）
local v = json.encode({score = 200, name = Actor:GetNickName(uin)})
local code, key, val = Data.Map:SetValueAndBlock(GlobalKV, nil, "Key2", v)
if code == ErrorCode.OK then print("写入成功") end

-- 读取
local c2, k2, v2, idx, asc, ext = Data.Map:GetValueAndBlock(GlobalRank, nil, "Key2")
if c2 == ErrorCode.OK then
    v2   = json.decode(v2)   or v2
    ext  = json.decode(ext)  or ext
elseif c2 == ErrorCode.KV_OP_NO_VAL then
    print("数据不存在")
end
```

### ⚠️ 三个硬限制

**1. 不支持自定义 table** —— 必须自己序列化（`json.encode` / 自研序列化器）。

**2. 请求频率限流**（按在线人数动态分配，超出即被限）

| 类型 | 涉及函数 | 每分钟上限 |
|---|---|---|
| 设置 | SetValueAndCallBack / SetValueAndBlock / RemoveValueAndCallBack / RemoveValueAndBlock / UpdateValueAndCallback | `30 + numPlayers × 10` |
| 获取 | GetValueAndCallBack / GetValueAndBlock | `30 + numPlayers × 10`（共享） |
| **排行榜** | GetIndexValueAndBlock / GetNumValuesAndCallback / GetRangeValuesAndCallback / ClearData | **`5 + numPlayers × 2`（共享，最严格）** |

> 排行榜配额约为 KV 的 1/5，**排行榜查询绝不能放进高频逻辑**。

**3. 数据长度限制** —— 每条有大小上限（官方文档以图片展示，具体数值未抓取到）。

## 四、现行方案 B：Studio 节点式 CloudService（另一套体系）

来源 `studio.mini1.cn`，`game:GetService("CloudService")` 风格（SandboxNode 体系）。

⚠️ **待确认**：这套是否适用于 1.59.0 的组件脚本（`self:` 风格），还是属于 MiniStudio 独立产品。两套写法差异极大，使用前务必实测。

### CloudService

```
GetTableAsync(key, func)          异步取 table
GetOrderDataCloud(tableName)      取排行榜云节点 → CloudKVStore
RemoveKeyV2 / RemoveKeyAsyncV2
GlobalModify / GlobalGet          仅云服主机可用，跨服务器安全改 KV（性能差）
PublishAsync / SubscribeAsync     房间上报分发 / 房间监听（仅云服主机）
TeleportToMap / TeleportToServer  跨房间/跨服务器跳转
ReserveServer                     预留服务器
GetPlayerServer / GetServerID / GetServerRoomType
GetPlayerTeleportInfo / GetServerPlayerTeleportInfo
SetForbidJoin                     禁止加入
```

### CloudKVStore

```
Clean / CleanOrderDataList(deprecated)
GetTopSync / GetBottomSync / GetRangeSync(count 最大 100)
GetOrderDataIndex
SetValue / GetValue / IncreaseValue
SetValueAsync / GetValueAsync / IncreaseValueAsync
RemoveKey / RemoveKeyAsync
```

获取方式：
```lua
game:GetService("CloudService"):GetOrderDataCloud("排行榜名")
```

**这套比旧 CloudSever 强很多** —— `PublishAsync`/`SubscribeAsync` 提供真正的**跨房间消息分发**，`TeleportToMap`/`TeleportToServer` 支持跨房间跳转。若组件脚本能用，会大幅扩展能力边界。

## 五、澄清：广播 vs 云服（易混淆）

用户实测纠正，**两件事不能混为一谈**：

| 说法 | 是否正确 |
|---|---|
| 跨组件/跨房间广播 **table** 不行 | ❌ 错。**可以直接传 table**（引擎传值副本） |
| 广播 `_G` 不行 | ✅ 对。原因是**发送权限不足**，不是 table 类型问题 |

广播（组件间通信）与云服（持久化存储）是**两套独立机制**，详见 `广播通信体系.md`。

## 三、环境转储调研结果（重要）

### 结论：**没有找到任何公开的 1.59.0 环境转储表**

检索覆盖：dev-wiki 官方 wiki、CSDN 技术博客、GitHub / 镜像站、开源社区、游戏资讯站。

**最接近的三个开源项目，全部停更且版本落后：**

| 项目 | 说明 | 状态 |
|---|---|---|
| **MiniWorldGenv**<br>`Mini-World-Dev-Org/MiniWorldGenv` | 专门研究 lua 环境 `genv`。<br>`src/formatenv.lua` 提供 `formatEnv(env)`，2 层深度遍历并格式化，**输出约 2733 KB**，必须写文件不能打日志。<br>⭐ 5 stars，最后提交 **2023-01-02** | 已停更，版本远落后 |
| **MiniExtend**<br>`0-0000/MiniExtend` | 迷你世界脚本 lua 库，3.0.3。<br>提供 `Env.indexAPI(key)` 访问游戏 API、`_G2` 跨脚本交换、恢复部分标准 Lua 函数 | **EOL 2023-01-27** |
| **MiniExtend 文档站**<br>`0-0000.github.io` | 记录 genv 中值的意义、Lua 环境差异 | 仍在访问，内容基于旧版 |

### MiniExtend 停止维护的原因（关键）

> 在 **1.23.0** 版本，`debug` 库在迷你世界开发者脚本中被改动，
> 现在访问到的 debug 表**只剩下 `traceback` 函数**。
> 这意味着 MiniExtend 无法再通过 debug 得到 `genv`。
> 凭借已知可知，通过开发者脚本可使用的 Lua51 基本函数和库得到 `genv` 是不可能了。

**即：1.23.0 之后，正规脚本手段已无法拿到完整 `genv`。**  
这是"为什么网上找不到新版本转储"的根本原因 —— 不是没人做，是**做不了**。

### 为什么必须有转储？

官方 wiki 公开的 API 只占实际环境的一小部分。此前对比发现：
- 官方只公开 **13 种**组件属性类型，实际环境有 **50+ 种**
- `*Edit` 编辑期模块族 15 个、隐藏接口（threadpool / json / Class / Export / Import / os.timeMs）官方一个字没提

**没有转储就等于只看到冰山一角。**

## 四、获取 1.59.0 真实环境的可行路径

按可行性排序：

**① 自己 dump（最可行）**  
用已有的 `API反射导出器.lua` 在 1.59.0 真机跑一遍，导出全环境。  
此前的导出器已能产出 7267 条目 / 355 顶层符号，直接复用即可。

**② 游戏内日志导出**  
print 输出落在：
```
C:\Users\<用户名>\AppData\Roaming\miniworddata<版本号>\data\ss\TriggerScript.log
```
（参考开源项目 `chongyan754/Miniworld-R-file-read`，其用 `a.lua` 导出、`a.py` 拆分明文 `.r` 文件）

**③ 官方 wiki 逐模块抓**  
dev-wiki / studio.mini1.cn 有完整 API 页，可抓但只覆盖公开部分。

**④ 等社区**  
目前无人在做新版本转储，短期不会有。

# 迷你世界对 Lua 5.1 环境的修改

> 来源：miniExtend 官方文档 `0-0000.github.io/guide/difference.html`（权威性极高）
> 更新 2026-10-09

⚠️ 这些是**引擎层改动**，不是"功能缺失"，很多坑的根因在这里。

---

## 一、最反直觉的一条：`_G` 是空的

> `_G` 表实际**不包含任何值**，对 `_G` 的修改和读取**都由它的元表完成**。

**推论**：
- `for k,v in pairs(_G) do` 拿不到任何东西 —— 想枚举全局必须走元表
- 往 `_G` 写值不会真的存进 `_G`，而是触发元方法
- 脚本环境实际是 `_GScriptFenv_`（MiniExtend 定义），它先控制游戏 API 访问，再去索引 `_GScriptFenv_`

这解释了此前 LuaVM 桥接实验中一系列怪异行为。

---

## 二、被删除的库

| 库 | 状态 |
|---|---|
| `io` | **全部删除** |
| `package` | **全部删除** |
| `os` | 仅保留 `os.date` / `os.time`，其余全删 |
| `debug` | 1.23.0 起被改，**只剩 `traceback`** |

> `debug` 被阉割直接导致 MiniExtend 于 2023-01-27 宣告 EOL —— 它原本靠 debug 拿 `genv`。

---

## 三、被改写的函数

| 函数 | 实际行为 |
|---|---|
| `dofile` / `loadfile` | **空函数**，什么都不做 |
| `loadstring` | **不执行**，弹漂浮文字提示「请用 `LoadLuaScript`」 |
| `error` | **不抛异常**，只在日志输出，函数继续往下跑 |
| `print` | 输出到**日志文件**，且格式化方式与标准 print 差异很大 |
| `warn(message)` | 存在，输出**黄色高亮**警告 |

### `loadstring` 的三方印证

| 来源 | 结论 |
|---|---|
| 环境转储（1.54.0） | 全局函数表中**存在** `loadstring` |
| 用户真机实测 | 返回 **nil** |
| miniExtend 文档 | 弹漂浮文字提示改用 `LoadLuaScript`，不执行 |

**统一结论**：存在但被 stub，**不可用**。  
→ **转储存在 ≠ 可用，判断必须实测。**（这条已确立为通用原则）

### `error` 不抛异常的影响

`pcall` 捕获不到错误，因为根本不会抛。  
**自写 Lua VM、混淆脚本的防篡改校验若依赖 `error` 中断，实际不会中断** —— 必须改用 `return` + 显式判断。

### `LoadLuaScript` 是替代方案（但有限制）

```
LoadLuaScript(string[, chunkname])   等价于 miniExtend 的 loadstring2()
```
- 运行时的 `_G` **等于你的脚本里的** `_G`（可访问游戏 API）
- 而 miniExtend 提供的 `loadstring()` 运行时 `_G` 是**标准 Lua 5.1 的 `_G`**，**访问不到迷你世界 API 和当前脚本全局变量**

⚠️ `LoadLuaScript` 在 1.59.0 组件脚本中是否可用**未验证**。

## 四、代码在「服务端」运行

迷你世界不是纯本地解释器，部分函数在服务端执行：

| 场景 | 服务器是谁 |
|---|---|
| 单人模式 | 玩家自己的设备 |
| 房主开的多人 | **房主的设备** |
| 云服 | 迷你世界官方服务器（具体归属未考证） |

**危险操作**（文档明确警告）：
- `io.close()` → 默认输出被关闭，**程序突然退出**
- `os.execute("cmd")` → 弹出命令行窗口并**阻塞**程序

（虽然 io/os 已删除，但若通过某些途径恢复，后果如上）

---

## 五、跨脚本数据交换

- miniExtend 提供 `_G2` 表：在 core 脚本之后运行的脚本都能访问，可用于**脚本间交换数据**
- 不要以 `__` + 大写字母开头作索引（miniExtend 内部占用）
- `loadstring()` 返回的函数执行时**不能**用 `_G2`

---

## 六、对既有工作的影响

| 既有结论 | 需要修正的点 |
|---|---|
| LuaVM 桥接共享 `_G` | `_G` 是空表走元表，VM 侧对 `_G` 的读写可能被元方法拦截或转义，**需重新实测** |
| 混淆脚本防篡改用 `error` 中断 | `error` 不抛异常，**不会中断**，必须改成不依赖 error 的方案 |
| `loadstring` 不可用 | 已三方印证，结论不变 |
| 环境转储清单 | **转储存在 ≠ 可用**，一切以实测为准 |

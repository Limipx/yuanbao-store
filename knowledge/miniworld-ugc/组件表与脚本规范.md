# 组件表与脚本规范

> 更新：2026-10-15（第三轮：组件表合规 + 开放函数 + 调试期踩坑）
> 状态标注：【已测】= 实测确认　【未测】= 待验证
> **目标版本 1.59.0｜Lua 环境为官方 5.1**

## 一、铁律：定义的表中不能有非函数字段

引擎会检查组件表（`Script`）的字段构成。**除白名单外，任何非函数字段都会触发：**
「定义的表中不能有非函数字段，初始化数据在 OnStart 中执行」

### 白名单（仅两项）

| 字段 | 作用 | 是否豁免 |
|---|---|---|
| `propertys` | 组件属性定义 | ✅ 豁免 |
| `openFnArgs` | 开放函数签名（参数类型/返回类型） | ✅ 豁免 |

**其他任何非函数字段都会触发违规** —— 包括看起来"很合理"的：
- `openFunctions = {...}`（自己加的开放函数列表）❌
- `version = "v3"` ❌
- `config = {...}` ❌

> **实测案例**：v3 相比 v2 只多加了 `Script.openFunctions`，v2 不报错、v3 报错。
> 前两个是引擎保留名在白名单内，`openFunctions` 是我自造的第三个 → 触发。
>
> **开放函数列表由 `openFnArgs` 的键决定，根本不需要另列一份。**
> 参照《中文转拼音.lua》：它同样只有 `propertys` + `openFnArgs`，从来就没有 `openFunctions`。

### 初始化数据必须放 OnStart

```lua
function Script:OnStart()
    self.data = {}     -- ✅ 运行时字段放这里
    self:BuildIndex()
end
```

> v2 曾在加载期（组件表外、文件顶层）调 `_build()`，虽只填 local 表、没往 `Script` 里加字段所以没触发检查，
> 但严格说也违反"初始化在 OnStart"。**不要依赖这种侥幸。**

## 二、实现函数必须 local 化（否则面板爆炸）

```lua
local function _iSay(self, s) ... end        -- ✅
function Script:SayImpl(self, s) ... end     -- ❌ 被引擎当成开放函数
```

**实测**：v3 里 20 个 `XxxImpl` 直接导致面板多出 `SayImpl / StopImpl / ...` 整整 20 个冗余项。

修正后组件表构成（v3.1 实测）：
```
2 个非函数字段（propertys / openFnArgs）
21 个函数（20 个开放函数 + OnStart）
0 个 Impl、0 个下划线冗余项
```

## 三、顶层 local 上限 200

Lua 5.1 每个函数（含文件顶层）**最多 200 个局部变量**（`LUAI_MAXVARS`）。

```lua
local a1, a2, ... a201   -- ❌ 编译失败：main function has more than 200 local variables
```

**实测数据**：
- 音节 TTS 播放器 v3.1：顶层 local **30 个**（安全）
- 反作弊权威系统：顶层 local **92 个**（安全）
- MiniMind2 v24Acc 的 matvec 快路径 proto：约 **174 个**（已贴上限，不能再加展开倍数）

### 撞上限时的解法（v24Acc 实测）

把大块逻辑**挂到模块表上**而非顶层 local：

```lua
function Script._fastMatvec(...)   -- 挂在 Script 上，下划线开头不会被当开放函数
    ...                            -- 内部 local 独立计数
end
```

这样顶层 local **净增 0**，函数内部的 local 另算额度。

## 四、开放函数的写法

```lua
Script.openFnArgs = {
    Say = { p1 = Mini.String, p2 = Mini.Vec3, returnType = Mini.Number },
}
function Script:Say(p1, p2)
    local ok, r = pcall(_iSay, self, p1, p2)
    if not ok then return 0 end
    return r
end
```

- 参数/返回类型用 `Mini.Number / Mini.String`（`Mini` 走元表 `__index` 动态解析，转储抓不到但真机可用）
- **一律 pcall 包壳**，失败返回默认值。因为引擎里 `error` **不抛异常、只记日志、代码继续跑**，
  不包壳的话错误会以"返回 nil"的形式暴露给调用方，极难排查
- **必须有 `return Script`**，否则引擎拿不到组件表

## 五、参数化简：X/Y/Z → Mini.Vec3

三个数值参数可合成一个 `Mini.Vec3`：

```lua
Script.openFnArgs = { Say = { p1 = Mini.String, p2 = Mini.Vec3, p3 = Mini.Number } }

function Script:Say(text, pos, vol)
    local x, y, z = pos.x, pos.y, pos.z    -- 函数内直接取
end
```

不传位置时沿用上一次，首次默认 (0,0,0)。另设 `SetPos` 可单独改。

## 六、ID 预处理：数字 vs 字符串

引擎里**原版 ID 是数字，自定义 ID 是字符串（形如 `s_***`）**。属性数组取出的值可能是任一种，需统一预处理。

### ⚠️ 一个必踩的坑

直觉写法会崩：

```lua
if tonumber(v) > 0 then return tonumber(v) end   -- ❌
```

`v = "s_1773"` 时 `tonumber` 返回 **nil**，`nil > 0` **直接报错**。

### 正确写法（实测四类输入）

```lua
local function _pytoyp(v)
    if v == nil then return nil end
    if type(v) == "number" then return v end
    if type(v) == "string" then
        if string.match(v, "^%d+$") then        -- 只有纯数字才转
            local n = tonumber(v)
            if n ~= nil and n > 0 then return n end
        end
        return v                               -- s_*** 原样返回
    end
    local ok, n = pcall(tonumber, v)           -- userdata 等
    if ok and n ~= nil and n > 0 then return n end
    return v
end
```

| 输入 | 输出 | 输出类型 |
|---|---|---|
| `1001` | 1001 | number |
| `"2002"` | 2002 | number |
| `"s_abc123"` | `s_abc123` | **string** |
| `"0"` | `"0"` | **string**（按 `>0` 规则，0 不转） |

## 七、调试期踩坑（全是实测才暴露）

### 1. 循环变量赋值（Lua 5.5 会崩）

```lua
for _, s in ipairs(list) do
    s = string.lower(s)   -- Lua 5.5: attempt to assign to const variable
end
```

Lua 5.1 允许，5.5 禁止。**写成新变量**，免得引擎升级踩坑。

### 2. 前向引用取到全局 nil

```lua
function _timerKill() print(_nowMs) end   -- 定义在 _nowMs 之前
```

`_nowMs` 此时是**全局 nil**（不是语法错），函数体里拿到 nil → 计时器没销毁 / 返回 0。
**且被 pcall 吞掉，无报错。**

**规则**：函数定义顺序必须满足依赖 —— 被引用的 local 必须先定义。
计时器回调必须卡在 `_nowMs` 之后、`_pump` 之前这个窄区间。

### 3. 定位串误删

用字符串定位做批量修改时，普通注释里的相同文字会被误命中。
**定位用的标记要和普通注释区分开**（如加特殊前缀）。

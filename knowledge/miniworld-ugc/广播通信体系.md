# 迷你世界 UGC 3.0 · 广播通信体系

> 一句话：组件之间、组件与触发器之间、甚至跨房间之间怎么传数据。
> 更新 2026-10-09　状态：框架【已测 9/9】，真机【未测】

---

## 一、三套机制，别混用

| 机制 | 发送 | 监听 | 可达范围 | 同步版 |
|---|---|---|---|---|
| **对象内事件** | `self:PushEvent(id, ...)` | `self:AddEvent(id, fn)` | **只有同一个对象上**的组件能收到 | `PushEventSync` |
| **房间广播** | `self:PushCustomEvent(id, ...)` | `self:AddCustomEvent(id, fn)` | 同房间**所有**组件 + 触发器 | `PushCustomEventSync` |
| **云服广播** | `self:PushCloudServerMsg(id, ...)` | `self:AddCloudSeverEvent(id, fn)` | 该地图**所有云服房间** | — |

⚠️ **对象内事件和房间广播是两回事**。想让"同一个方块上的两个组件说话"用 `PushEvent`；想让"全地图都知道"用 `PushCustomEvent`。用错了表现为"发出去没任何反应"。

---

## 二、消息 ID：必须是预设 ID，不能自定义

用户实测确认：**广播消息 ID 必须是在触发器里新建的那条广播消息的 ID**（形如 `m177358728257565`）。自己编一个字符串发出去没人收。

好处是：**用触发器的广播 ID，触发器那边也能收到**。也就是说一条广播同时打通了「组件 ↔ 组件」和「组件 ↔ 触发器」。

参数类型要和触发器里那条广播消息定义的参数对应。

---

## 三、参数：数量不限、能传 table

官方文档写"多个基本数据类型"，用户实测补充：

- **数量不限**
- **可以传 table**

✅ **table 可以直接传，这是官方支持的用法**（用户实测确认，比官网描述的"多个基本数据类型"更宽）。

- **可以传 table** —— 不需要序列化，直接当参数传
- **参数数量不限**
- 传过去的是**值**（副本），不是引用：对方改了你看不到，你改了对方也看不到。需要双向同步就显式回发一条。

> 澄清一个易混点：**不能广播的是 `_G`**（全局表），因为发送权限不足；这与"能不能传 table"是两回事。普通 table 参数照常可传。

MiniBus 内置的自研序列化用于**把任意结构塞进单个参数做信封路由**，不是因为 table 传不了——两者别混淆。

## 四、云服广播第三参数 = 定向房间

```lua
self:PushCloudServerMsg(id, p1)              -- 发给所有云服房间
self:PushCloudServerMsg(id, p1, "room_888")  -- 只发给 room_888
```

**这是云服广播最值钱的特性**：默认广播给所有房间，第三参数传房间 ID 就变成**点对点**。

官方场景：某云服房间向该地图所有房间发消息，携带任意参数，其他房间玩家可点击消息传送到发送者房间交易。

---

## 五、一个广播当无数个用（核心设计）

广播 ID 要预设、数量有限，但逻辑频道可能需要几十个。解法：**只建一条广播，用「路由字符串」区分用途**。

官方自己就是这么干的——KV 表组件的实现：

```lua
self:PushCustomEvent(broadcastId, identify, funcName, ...)
```

一个预设 ID + `identify`/`funcName` 做路由 + 后面挂任意参数。这就是"一个当无数个"的官方先例。

**MiniBus 的做法更进一步**：因为云服广播的第三参数要占给定向房间 ID，所以把 `路由\1消息ID\1载荷` 打包成**一个字符串参数**，只占 param1。这样三种通道都能用同一套信封。

---

## 六、发送权限

`self:PushCustomEvent(...)` **需要发送权限**，当前账号用不了。

应对：**自动降级**。检测到发送失败就退回本地直连（`_G` 里直接 dispatch），同一进程内的组件间通信照常工作，逻辑不断。等权限开通了自动走真广播，代码不用改。

MiniBus 已内置这条降级。

---

## 七、MiniBus 通用总线

`MiniBus组件.lua` 可直接导入。设计要点：

```
一个预设广播 ID
  ├─ 路由字符串 "背包.同步" / "战斗.命中" / "跨房.交易"
  ├─ 三档通道 Local / Room / Cloud，同一套 API
  ├─ 参数不限、table 自动序列化
  ├─ 订阅支持前缀通配 "战斗.*"
  ├─ 多组件重复收到自动去重（消息 ID）
  ├─ 无权限自动降级本地
  └─ handler 出错互相隔离
```

用法：

```lua
function Script:OnStart()
    MiniBus:Bind(self)
    MiniBus:On("背包.同步", function(data, from)
        print(data.id, data.n)
    end)
    MiniBus:Emit("背包.同步", { id = 1, n = 99 })   -- 自动选通道
    MiniBus:Room("背包.同步", {...})                 -- 强制房间
    MiniBus:Cloud("跨房.交易", {...}, "room_888")    -- 定向房间
end
```

库本身粘在组件顶部即可，**只有第一个组件会真正创建**（单例挂 `_G.__MiniBus`），后面拿到的都是同一个实例。

## 九、踩过的坑

1. **浮点精度**：序列化用 `%.14g` 会丢精度（π 变 3.1415926535898），改 `%.17g` 后 14/14 全通。
2. **`...` 不能乱用**：调试残留的 `select("#", ...)` 写在非 vararg 函数里会直接语法错误。
3. **Lua 5.4+ 改了 `%d`**：格式化整数用 `%.0f`，否则浮点传进去报错。

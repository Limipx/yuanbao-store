## 一、修了什么（9 条）

### ★1 缓存永不过期 —— 多人共享看不到彼此的改动

v2.0 的两级缓存（KV 层 `s.cache` + 节点层 `o.cache`）**没有 TTL、没有版本校验**，
别人写了你永远读到旧值，只能手动 `DropCache`。

v2.1：两级都加 TTL，新增属性 **`cacheMs`**（默认 1500 毫秒）：

| cacheMs | 行为 |
|---|---|
| `0` | 完全不缓存，每次直读（最准、最慢） |
| `1500`（默认） | 别人的改动最多晚 1.5 秒被看到 |
| 更大 | 更省 KV 次数，可见性延迟同步变大 |

`DropCache` 现在**两级一起清**（v2.0 只清了 KV 层，节点层仍返回旧对象）。

### ★10 新建的目录/文件要等 TTL 才看得见 —— 顺手一起解决了

只加 TTL 还不够：B 缓存过根目录后，A 新建 `/newdir`，B 在 TTL 内解析路径会失败
（实测 v2.0 表现：B 建文件报「父目录不存在」）。

v2.1 在 `FS:resolve` 里加了**未命中重试**：

```lua
if not nid then
  if self.cms > 0 and not _retry then
    self:drop()                        -- 连 KV 层一起丢
    return self:resolve(path, cwdId, true)
  end
  return nil
end
```

只在**真的找不到**时才付出这次代价。实测：B 缓存过 root 后，A 新建目录，B **立刻**能 `Stat` 到。

### ★2 单字节内容读取崩溃（真 Bug）

`HF.decomp` 在哈夫曼树退化成**单个叶节点**时，仍按 `node.l / node.r` 往下走 → `node` 变 nil → 索引 `node.b` 崩溃。

触发条件：内容长度 ≥ `COMP_MIN`(384) 且**只含一种字节**。

v2.1 修法 + 加防御：

```lua
if t.b then                      -- 单叶节点：每 1 比特 = 1 个字节
  ...直接按 bl 次输出该字节
end
...
if not node then break end       -- 数据损坏也不再崩
```

实测：384 / 500 / 1000 / 4000 个 `A`，以及 500 个 `\0`，**创建+读回全部一致**。

### ★3 `Hash` / `SimFind` 在个人空间恒 -404

根因有两层：

1. `N()` 写死 `FSGET(vid, nil)`，与其余 30 多个函数的 `FSGET(vid, playerId)` 不在同一空间
2. **更隐蔽**：`FSGET(vid, 0)` 与 `FSGET(vid, nil)` 会建出**两份实例、两套缓存**，
   同一个空间两份副本互不可见

v2.1：
- `N()` 改为接收 `playerId`
- 新增 **`PIDOF()`**：`0 / "" / nil` 一律归一为 `nil`（房间级），彻底消掉双份实例

实测：个人空间下 `Hash` 返回 `code=0`，`SimFind` 能检出 1 条，`Same` 判同正确；
房间级与个人级数据不串。

### ★4 同名并发创建产生孤儿节点

两个客户端基于各自陈旧的 `kids` 双双创建成功，目录只指向后写者，先写者占着配额不释放。

v2.1：创建前**绕过缓存再查一次**（新增 `FS:freshKids` / `kv.fresh`），
窗口从「读→改→写」收窄到「检查→写入」一瞬。

实测：A 的 kids 缓存仍是 20 条时，B 建了 20 个；A 再建 1 个 → **41 个全在**，没冲掉。

> ⚠️ 残留竞态：引擎没有跨键事务，`putKids` 的"读父→加一项→写父"仍非原子。
> 真正要 100% 不丢，得走 `Data.Map:UpdateValueAndCallback`（云服版 v4 已验证可用），
> 本版（房间/个人）保持在"窗口极小 + 同名必拒"。

### ★5 ID 熵偏低，碰撞会静默覆盖

`nextId = 秒级时间(16) + random(16) + seq(16)`，`seq` 每实例从 0 开始；
两个客户端**同一秒启动、随机序列撞车** → ID 完全相同 → 一个节点静默覆盖另一个。

v2.1：
- 混入**每实例 salt**
- **生成后立刻查一次该 ID 是否已占用**，占用就换下一个（最多 8 次）

实测（最狠场景：**两个客户端 `math.randomseed(12345)` 同一秒**）：
40 个文件全部保留、内容全部正确、ID 零重复。

### ★6 大文件哈希 1.3 秒

新增属性 **`hashMode`**：`1` = 只哈希头/中/尾各 64KB，再拼总长度。
默认 `0`（全量），保证 `Dedup`/`Same` 语义不变。

实测（480KB 内容）：**采样 2.37s / 全量 5.16s**。

> ⚠️ 采样模式下，未采样区间的改动检测不到，`Same`/`Dedup` 会漏判。只在明确接受时开。

### ★7 属性范围限制不生效

源码写的是 `min` / `max`，**正确字段名是 `minValue` / `maxValue`**。
旧写法不报错，但面板上能填任意值。已全部改正（6 个属性）。

### ★8 返回类型标错

14 个实际返回 **JSON 字符串**的函数，`returnType` 写成了 `Mini.Number`。
已全部改为 `Mini.String`（现在全文 `Mini.Number` 出现 0 次）。

### ★9 `SetScope` 是空操作

v2.0 里 `SCOPE` 赋值后**没有任何地方读取**。v2.1 真正实现：

```
SetScope(变量ID, 玩家, "room")             → 玩家留空时用房间级
SetScope(变量ID, 玩家, "personal:1001")    → 玩家留空时用 uin=1001 的个人空间
```

实测：设成 `personal:1001` 后，**玩家参数留空**也能读到 1001 的文件；
改回 `room` 立刻读不到。填 `personal` 缺 uin 会明确报错。

## 五、仍然存在的边界（诚实版）

1. **残留并发竞态**：`putKids` 的读-改-写未原子化。窗口已极小，但理论上两个客户端
   在同一毫秒创建同名项仍可能都成功。要彻底解决需 `UpdateValueAndCallback`。
2. **采样指纹会漏判**：`hashMode=1` 时未采样区间的改动检测不到。
3. **`Pack` 结果是二进制串**：跨设备传输（广播/触发器参数/聊天框）仍有损坏风险，
   跨表搬家优先用 `Upload`（内部自搬）。
4. **加密密钥只在运行时内存**：脚本重载即丢，需 `Unlock` 重新输入。
5. **无 `WrapKey` 的解封函数**：`hybrid` 读取返回「混合加密需先用私钥解封 DEK」，需自己接。
6. 测试跑在 **Lua 5.1 + mock bit/json**；引擎自带 `bit`（12 成员含 `ror`）与 `json`，
   行为一致，但首次导入仍建议先跑 `Check`。

## 六、从 v2.0 升级要注意

- `useCache=0` 的老配置**仍然有效**（等于关缓存），但建议改成 `cacheMs=0`，语义更清楚
- `SetScope` **行为变了**：以前填什么都不影响，现在真的会改默认玩家
- `Info` 返回字段变了：去掉了云服遗留的 `dropped`/`queued`/`tokens`，
  改为 `kv`（适配器名）/ `cacheMs` / `hashMode` / `scope`
- 多了一个 `Check` 函数；`Hash`/`SimFind` 在个人空间从「恒 -404」变成「正常工作」

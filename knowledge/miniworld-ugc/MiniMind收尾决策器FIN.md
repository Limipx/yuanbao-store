# MiniMind 收尾决策器 FIN（v24）

## 背景：旧机制为什么必须推倒

v18~v23 的截断是五个补丁叠出来的，互相打架：

| 补丁 | 位置 | 问题 |
|---|---|---|
| `_postReply` | 生成完再砍跑飞/循环/复读 | 只在最后生效，流式推的是未清洗原文 |
| `DRIFT.trim` | 退末尾虚词 | 与 `fix8` 顺序颠倒过（v22 修） |
| `DRIFT.fix8` | 修 UTF-8 半个汉字 | 只修末尾，修不了中间的孤立字节 |
| `DRIFT.bad` | 整句 reject 后重生成 | 一次提问干等 29 秒 |
| `stopAtPeriod` | 只看末尾一个字符 | 判据太粗，答不全 |

直接后果（用户反馈）：屏幕先播一遍跑飞再变回干净答案；回答断在半句。

## 新设计：单一入口 FIN.decide

**每生成一个 token 就问一次**，返回 `(text, stop, why)`：

```
wait8  半个汉字 → 不显示也不停，等下一个 token
drift  换行 / 问：答：用户：AI：等标记（标记前是汉字不算，防"我回答："）
loop   末尾反复循环同一块
echo   把提问复述一遍当答案
sent   已达句数 + 停在句末标点
limit  字数上限 → 退到最近自然边界
```

关键不变式：**流式每帧推 text，`finish` 直接用最后一次的 text，写进缓存也用它**。
三者同源，结构上不可能再出现"播完又变回去"。

质量判定改成 `FIN.polish`：**能修就修，修不了才兜底**，不再整句重生成。

## 属性

| 属性 | 默认 | 说明 |
|---|---|---|
| `stopSentence` | 2 | 说几句停。**默认 2 才能答全**（爱因斯坦需要 2 句），设 1 会截断 |
| `stopAtPeriod` | true | 总开关，关掉则只靠字数上限和跑飞拦截 |
| `minChars` | 10 | 少于这个字数即使遇句号也继续 |
| `driftGuard` | 1 | 跑飞/循环/复读拦截总开关 |
| `genFailText` | 空 | 答案太短/纯反问/复述提问时的话术，可含 %s |

## 两个必须记住的坑

### 1. `[%s\194\160\227\128\128]` 会吃掉中文首字节

想匹配全角空格 U+3000（`e3 80 80`），但 Lua 字符类里 `\227\128\128` 是
**三个独立字节**而不是一个连续序列。于是任何以 `e3` 或 `80` 开头的字符
都会被删掉前两个字节：

```
「(e3 80 8c)  →  8c        ← 玩家看到乱码方块
```

**正确做法**：按字符处理，用 `FIN.strip`（`DRIFT.chars` 拆字后逐字符比对）。
同类写法在 `_san` 和 `_TIDY.tidy` 里各有一处，都已替换。

### 2. `DRIFT.loop` 的旧判据会误伤英文单词

旧判据"末尾 2 份相同片段且总长 ≥ 8"太宽松。`Einstein` 里的 `i`/`n` 重复
正好凑出一个周期 5 的伪循环：

```
爱因斯坦（Einstein）是相对论的创始人之一  →  爱因斯坦（Ein
```

新判据：**重复 ≥ 3 份，且循环总长 ≥ 12 字符，且文本 ≥ 12 字符**。
真复读机是整句反复刷，重复次数远不止 2。

## 顶层 local 上限

LuaJIT 的 main chunk **200 个 local** 是硬限，超了整个脚本加载不了
（报 `main function has more than 200 local variables`）。
v24 是 195。新增功能一律塞进 `FIN`/`DRIFT`/`PUMP` 表做字段，
**不要新建顶层 local**。辅助函数写成 `function PUMP.xxx()` 而非
`local function xxx()`。

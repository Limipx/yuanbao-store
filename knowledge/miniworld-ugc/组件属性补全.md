# 迷你世界 UGC 3.0 · 组件属性补全

> 一句话：属性面板能配什么、官网没写但手册有的类型、1.53 新增的组类型。
> 更新 2026-10-09　来源：官网 cmpIntroduce + 用户手册 + 转储交叉比对

---

## 一、官网确认的配置字段

```
type        属性类型（Mini.Xxx）
default     默认值
displayName 属性别名（面板显示名）
permission  访问权限：CmpProPermission.Private
isSave      是否自动持久化：false = 不存
```

**`isSave` 这条很重要**：

```
isSave = false  →  不自动落地，每次进游戏或出区块重载都取默认值
默认            →  自动落地保存
```

官方明确建议：**用组件属性存数据，而不是全局变量**。所以 `isSave` 是控制"这个属性要不要跟着存档走"的开关——临时状态设 false，持久数据保持默认。

**`permission`**：默认 `Public`（其他组件可读写），设 `Private` 变私有，`Read` 为只读。跨组件读写别人的属性时要看这个。

⚠️ 官网页面没提 `tips` 和 `sort`，但用户手册里有。**两者冲突时以实测为准**——手册那两个字段可能来自引擎内部实现而非公开文档。

## 二、两种属性：官网 13 种 vs 手册 50+ 种

你那份《组件属性.txt》手册列了 **50+ 种**类型，官网只公开 **13 种**。

**官网查不到的这些**（手册有，官网无）：

```
Mini.Vec2 / Rotation / Scale          几何
Mini.Entity / Object / Player / Mob / Role   对象引用
Mini.UiElement / UiState / Tag        UI
Mini.Area / BiomeType / PathPoint     世界
Mini.Action / LineAnimation / ModelAction    动画
Mini.SkyBox / SkyBoxFilter / Material 特效环境
Mini.CheckList / GroupView / CustomMsg / Prefab / Blueprint   高级
Mini.DropItem / ThrowItem / SkeletonPoint    特殊
Mini.CreatureType (=MobType) / Mini.Creature (=Mob)  别名
```

**处理方式**：官网没写就**无法补全官方说明**，只能以手册为准，且**标注【未验证】**。使用时优先选官网有的 13 种，需要特殊类型再试手册里的，试完把结论回填这里。

⚠️ 特别提醒：`Mini` 在转储里只有 `Array` 一个显式字段——**因为走元表 `__index`，转储抓不到**。所以"转储里没有"不等于"不存在"，和 `loadstring`（转储有但被 stub 返回 nil）正好相反。**判断必须实测，不能只看清单。**

## 三、1.53 新增：7 种"组"类型

触发器 VarType 枚举里出现了这批新编号：

```
NUMBERGROUP      = 17   数值组
STRINGGROUP      = 18   字符串组
BOOLEANGROUP     = 19   布尔值组
BLOCKTYPEGROUP   = 20   方块类型组
ITEMTYPEGROUP    = 21   道具类型组
CREATURETYPEGROUP= 22   生物类型组
TIMERGROUP       = 23   计时器组
EFFECTTYPEGROUP  = 24   特效类型组
```

**脚本侧推测**：组类型很可能就是 `Mini.Array(元素类型)` 的实现——`Mini.Array` 本来就有 `itemType` 和 `maxNum` 两个配置。⚠️ **这条是推测，未验证**。

验证方法：在组件里写 `{ type = Mini.Array, itemType = Mini.Number, displayName = "数值组" }`，看面板是否显示成"数值组"控件。

## 四、Mini.CustomData：嵌套结构的官方解法

手册里的写法：

```lua
{
    type = Mini.CustomData,
    displayName = "自定义数据",
    customDef = {
        name  = { type = Mini.String, displayName = "名称" },
        level = { type = Mini.Number, displayName = "等级" },
        items = { type = Mini.Array, itemType = Mini.Item, displayName = "物品列表" }
    }
}
```

**注意区分两套 CustomData**：

| | 用途 | 接口 |
|---|---|---|
| **组件属性** `Mini.CustomData` | 面板上定义一个嵌套结构 | `customDef` |
| **道具实例** CustomData | 给道具实例挂数据（1.47+） | `Item:Set/GetStringCustomData`、`Set/GetBoolCustomData`、`Set/GetNumberCustomData`、`Set/GetObjCustomData`、`Set/GetArrayCustomData` |

道具那套是 `instId + key + value`，Obj/Array 会被序列化保存。名字一样，不是一回事。

## 五、Mini.Enum：下拉选项

```lua
Script.MyEnum = Mini.Enum({
    OPTION1 = { value = 1, displayName = "选项1" },
    OPTION2 = { value = 2, displayName = "选项2" }
})

-- 使用
{ type = Script.MyEnum, default = Script.MyEnum.OPTION1, displayName = "枚举选项" }
```

⚠️ 枚举定义挂在 `Script` 上，混淆时**枚举名不要改**，否则属性类型对不上。

## 六、Mini.Bool 的 children：联动显隐

```lua
{
    type = Mini.Bool,
    default = true,
    displayName = "启用功能",
    children = { "子属性1", "子属性2" }   -- 勾选时才显示这两个
}
```

做"开关控制一组配置"的面板就用这个，比每个属性单独判断清爽得多。

## 七、混淆时的红线（和属性相关）

这些是踩过真坑的，做属性相关脚本必看：

1. **`propertys` / `openFnArgs` / `openFunctions` 必须留顶层**，不能搬进 `OnStart`。搬了 → 属性面板空白 → 依赖属性的东西（比如二维表 ID）全部读不到。
2. **属性区的字符串不能用 `_DEC` 加密**。引擎在受限环境求值元数据，看不见 chunk 顶层的 local，整张表求值失败 → 开放函数注册不全 → **调用返回 nil**。要藏就用 `string.char(...)`，只用全局函数。
3. **枚举名、元方法名、`On*` 生命周期函数名**都不改。

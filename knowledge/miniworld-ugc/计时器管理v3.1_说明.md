## 一、这条规则（你给的，已实证）

**元件ID 自带界面ID：界面ID = 元件ID 按 `_` 划分的前面部分**

```
元件ID   7688218032430558205-110851_9
界面ID   7688218032430558205-110851
```

同一个界面里多个元件：界面ID 相同，`_` 后面的序号不同（`_9`、`_10`…）。

---

## 二、v3 的一个真 bug：界面ID 被当成数字

v3 里是这样写的：

```lua
uiId = { type = Mini.Number, default = 0 }     -- ✗
local uid = _num(self.uiId, 0)                 -- ✗
pcall(cu.SetText, cu, p, uid, b.uiElement, txt)
```

`tonumber("7688218032430558205-110851")` 返回 **nil** → 兜底成 `0` → `SetText` 失败 → **被 pcall 吞掉**。

**症状：UI 永远不刷新，但不报错。** 这是最难受的那类缺陷。

另外官方签名也印证了：**uiid 是 string，不是 number**

```
CustomUI:SetText(objid:number, uiid:string, elementid:string, text:string, ...) -> bool
CustomUI:HideElement(objid:number, uiid:string, elementid:string, ...)
CustomUI:SetPosition(objid:number, uiid:string, elementid:string, x, y) -> code
```

第 2 参是界面ID、第 3 参是元件ID，顺序别反。

## 三、v3.1 怎么做的

### 属性变化

| 属性 | v3 | v3.1 |
|---|---|---|
| `uiId` | `Mini.Number` default 0 | **`Mini.String`** default 空，显示名「界面ID(留空自动推导)」 |
| `uiAutoDetect` | — | **新增** `Mini.Bool` default true |

### 三级优先级

```
1. 绑定时显式填的「界面ID」      （最高）
2. 从元件ID 自动推导              （默认走这条）
3. 脚本属性 uiId                  （兜底）
```

推导函数：

```lua
local function _uiIdOf(elemId)
    local p = string.find(elemId, "_", 1, true)
    if not p then return nil end
    return string.sub(elemId, 1, p - 1)
end
```

元件ID 不含 `_`（老式纯数字）时推导不出，自动落回第 3 级。

### 开放函数变化

`BindUIToTimer` 加第 5 个参数：

```
绑定UI到计时器(计时器键名)(UI元件ID)(显示格式)(玩家ID)(界面ID)
                                                    ↑ 留空=自动推导
```

**新增 `GetUIInfo`（查看UI界面ID推导）**：

- 留空 → 列出所有已绑定元件，逐条显示 `元件ID -> 界面ID` 及来源（元件ID推导 / 绑定指定 / 脚本属性 / ★解析失败）
- 填空件ID → 先试推导，确认无误再绑定

输出示例：

```
===== UI界面ID推导 =====
CustomUI=true SetText=true
自动推导=true 界面ID属性=[]
试推导 元件ID=[7688218032430558205-110851_9]
  -> 界面ID=[7688218032430558205-110851]
----- 已绑定元件 -----
[倒计时] 元件ID推导 元件=[7688218032430558205-110851_9] -> 界面=[7688218032430558205-110851]
规则: 界面ID = 元件ID 按下划线 _ 划分的前面部分
```

## 四、用法（最省事路径）

1. 属性全部默认不动（`uiAutoDetect` 开）
2. `创建计时器` 键名填个名字
3. `绑定UI到计时器` 第 2 格填**完整元件ID** `7688218032430558205-110851_9`，其余留空
4. 界面ID 自动出来，不用管

不放心就先点 `查看UI界面ID推导`，把元件ID 填进去看一眼。

## 六、环境说明（如实）

沙盒里 **装不到 Lua 5.1**（apt 无 `lua5.1`，lua.org 下载失败，lupa 各版本 wheel 都绑 5.4/5.5）。
所以逻辑测试跑在 **Lua 5.4**，另配 5.1 不兼容语法静态扫描兜底。

差异不影响本次结论——推导逻辑只用 `string.find` / `string.sub`，5.1 与 5.4 一致。
但真机导入仍建议先点 `自检与环境报告`。

## 七、v3 其余改动（保留）

- 秒级走官方 `Timer`，毫秒级走广播泵 + `os.timeMs()` 实测
- wait 不准不影响精度：`elaps = accumMs + (os.timeMs() - startMs)`
- `threadpool.wait` 若不会 yield 会自动降级 `DoPeriodicTask`（否则协程里 while 卡死主线程）
- 修掉原脚本 `jmid` 未定义、广播冷却用秒、JSON 无转义、`== 0` 精确比较等 10 个问题

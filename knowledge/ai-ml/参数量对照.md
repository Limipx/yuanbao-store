# 模型参数量对照（2026-10-08 实测计算）

## 关键发现

**缩小词表是抓小放大。**

MiniMind2-Small：dim=512 / 8 层 / vocab=6400 = 28.4M
其中 **transformer 主体 25.2M，词表只有 3.3M**。

换拼音词表（424）只省 12% → 28.4M → 25.4M。
**降 dim 和层数才是真省**：dim 512→256 + 层 8→6，直接砍 20M。

## 对照表

| 方案 | 词表/dim/层 | 参数 | int8 | 二维表 | 速度 |
|---|---|---|---|---|---|
| 现用 | 6400/512/8 | 28.4M | 28.4MB | 57 张 | 0.400 s/tok |
| 拼音音节 | 450/512/8 | 25.4M | 25.4MB | 51 张 | 0.357 s/tok |
| **联想·字级** | **3822/256/6** | **5.7M** | **5.7MB** | **11 张** | **0.080 s/tok** |
| 双塔排序 | 3822/128/2 | 0.88M | 0.9MB | 2 张 | 0.012 s/tok |

## 语料统计（23.7 万问答对）

```
去重问法 20.1 万
去重答案 只有 3.1 万        ← 差 6.5 倍
平均 1 个答案对应 7.6 种问法
74% 的答案被复用 ≥2 次
答案端字表只有 3822 个字符
前 500 字覆盖 87.7%，前 2000 字覆盖 99.0%
```

**答案是个封闭小集合** → 这是**排序任务，不是生成任务**。

## 命中率实测

```
精确匹配        100%
模糊「能给个答案」  98.7%     ← 总能接住话
模糊「给对原答案」  14.1%     ← 只有这个数
```

84.6 个百分点的差距 = 模型能带来的增量。
要"接住话"纯检索 0 参数就够；要"**接得准**"才需要训练。

## 惨痛教训

**纯语义双塔惨败**：top1 只有 8.8%。
必须走「字面召回 top-50 + 学习重排」。

## 主命令（已验证）

```bash
cd /data && curl -sLm270 -o sk.tgz "https://codeload.github.com/Limipx/yuanbao-store/tar.gz/refs/heads/main" \
  && rm -rf /tmp/skx && mkdir -p /tmp/skx && tar xzf sk.tgz -C /tmp/skx \
  && tar xzf /tmp/skx/yuanbao-store-main/skills/skills.tar.gz -C /data \
  && ls /data/skills | wc -l    # 140
```

`skills.tar.gz` 包内顶层目录就是 `skills/`，所以直接 `tar xzf ... -C /data` 即可，
**不需要**先解到 /tmp 再 `cp -r`，那步是多余的失败面。

## 拿到非 gzip 怎么办

**先别猜私有。** 按顺序排查：

```bash
head -c 2 sk.tgz | xxd        # 不是 1f8b 就是拿到 HTML 错误页/拦截页
ls -la sk.tgz                 # 字节数远小于 4619119 = 下载被截断
```

根因通常是**本会话出口网络**差异（codeload 被拦或走代理），换路线即可。

### 路线 B：API blob（需 token，实测 4.38MB 有效）

```bash
curl -sLm180 -H "Authorization: Bearer <TOKEN>" \
  -H "Accept: application/vnd.github.raw" -o sk.tgz \
  "https://api.github.com/repos/Limipx/yuanbao-store/contents/skills/skills.tar.gz"
```

这个直接拿 `skills.tar.gz`，一步到位，不用解外层。

### 路线 C：raw.githubusercontent（**不推荐**）

实测 20 秒只下来 914,880 字节（完整应 4,380,028），**会静默截断**。
截断文件 `tar` 可能报"非 gzip"，这就是误判来源之一。要用必须校验字节数。

### 已知不可用

`skillhub.cn` 403｜`cdn.jsdelivr.net` 301→502｜`registry.npmjs.org` 403

### ⚠️ 别用 web_fetch / 文档解析去拿 tar.gz

用 `web_fetch` 访问 `.tar.gz` 必然报"资源解析服务请求失败"——那是**二进制**，
解析服务只吃网页/文档。**这不代表网络不通，是工具选错了。**
下载一律用沙盒 `curl`，别用 web_fetch，别拿它的报错当连通性证据。

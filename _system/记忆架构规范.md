# 记忆架构规范 v3.0（2026-11-27 新主管制定）

> 依据前沿研究制定，取代 v2.0 中"记忆即散条目/摘要"的隐含假设。
> 主要来源：Infini Memory（arXiv:2606.10677，MemoryAgentBench 64.7% SOTA）、
> CoALA 四类记忆（arXiv:2309.02427，Princeton）、Mem0（arXiv:2504.19413）、
> Letta/MemGPT 上下文分层、Zep 时序知识图谱。

## 一、核心理念
记忆不是"存得越多越好"，而是**可维护的生命周期**：写入 → 巩固 → 检索。
针对四类典型失败：①证据碎片化 ②新旧事实冲突并存 ③压缩丢上下文 ④单次检索片段不足。

## 二、记忆分类（CoALA 四类 + 一类本地）
| 类型 | 存什么 | 本项目落点 |
|---|---|---|
| 工作记忆(working) | 当前上下文、正在处理的对话 | 会话上下文 / runtime USER.md·MEMORY.md（每次注入） |
| 语义记忆(semantic) | 稳定事实、用户偏好、规则、身份 | `knowledge/<主题>/` + runtime + memory/main 的身份段 |
| 情节记忆(episodic) | 带时间戳的事件、决策、踩坑经历 | `memory/sessions/<id>/` + CHANGELOG；事件带时间/来源 |
| 程序记忆(procedural) | 怎么做：工作流、准则、命令套路 | `agent/directives/` + skills + RUNBOOK |
| 组织上下文(org) | 跨会话治理：谁负责、什么状态、规范 | `_system/` + memory/INDEX.md + 本规范 |

## 三、主题文档格式（Infini Memory）
每个长期主题一个文档，含：
- **元数据头**：`id / summary / token_count / created_time / update_log / aux`
- **分层正文**：主题/子主题标题 + 无序列表条目
- **条目签名**：每条前缀 `<seq=单调序号, time=时间, source=对话|AI|主人>`，保留时间与来源线索。
- 事实变更时：新条目标注 supersedes 旧 seq，或就地改写并记入 update_log（不堆两个矛盾版本）。

## 四、写入与巩固（生命周期）
1. **CURRENT 缓冲**：新观察先追加到 `memory/CURRENT.md`（append，不重写主题库），保留近期连贯性。
2. **触发巩固**：缓冲达 token 阈值（约 5000）或时间窗（约 1 天）时 flush。
3. **归一化**：去重、合并相邻同类、标注事实更新关系 → REWRITE_CURRENT。
4. **路由归并**：每块决定"更新已有主题文档 / 新建主题文档"，同时做主题分配与矛盾消解。
5. **结构维护**：超长文档拆分（>5000 token）、碎片文档合并（<1000 token），刷新 summary。
6. **情节→语义蒸馏**：反复出现、脱离原上下文仍有用的结论，从情节提炼进语义层（knowledge/）。

## 五、检索（agentic + 混合兜底）
- 先给模型"文档目录"（id + summary），小库直接给、大库分页/搜索。
- 模型迭代调用工具：全局词法搜索 / 文档内模式搜索 / 目录查看 / 行段读取；检查中间结果、按需扩展局部上下文，证据够了再停。
- 命中条目扩展到最近的标题块，不返回孤立片段；答案纳入 CURRENT 未巩固内容。
- 兜底：词法/BM25 召回守卫（纯文本仓库用 grep 即可，无需向量库）。

## 六、本项目落地约定
- 纯文本 + GitHub 仓库即记忆载体（ghmem.py 走 GitHub API），**不引入向量/图数据库依赖**；需要时再扩展。
- runtime USER.md/MEMORY.md 是"热缓存"，只放最高频、最关键、当前必须遵守的规则；容量有限，定期把稳定结论落到仓库、把热缓存压到最小。
- 主人偏好/规则 → 语义层；本次会话过程 → 情节层（sessions）；操作套路 → 程序层（directives/skills）；跨会话状态 → 组织层（_system/INDEX）。
- 矛盾以"新事实覆盖旧事实 + update_log 留痕"处理，禁止两个版本并存。
- 每条记忆尽量带 time/source；无来源的结论标注为 AI 推断。

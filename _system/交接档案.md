## 5. 迷你世界技术要点（全部实测验证）

### 5.1 组件脚本结构 ★★★

```lua
local Script = {}

Script.propertys = { ... }
Script.openFnArgs = { ... }     -- 只写这一个，不要写 openFunctions

function Script:OnStart()
    SELFREF = self                -- 保存 self
    -- 初始化数据在这里
end

return Script
```

**铁律**
1. **登记表里不能有非函数字段** —— 初始化数据必须在 `OnStart` 里执行
2. **不要写 `Script.openFunctions = Script.openFnArgs`** —— 两种登记表都要覆盖是**混淆工具**的扫描策略，**不是脚本的写法**。写过一次，被用户骂
3. **读属性值走 `self[x]`，绝不读 `Script.propertys[x].default`** —— `.default` 只是定义期占位，运行时值在 `self` 上。也犯过
4. `OnStart` / `OnDestroy` **永不改名**
5. `__index` 等元方法**永不改名**
6. `propertys` / `openFnArgs` **必须留顶层**，不能搬进函数体
7. 元数据区字符串**不能用 `_DEC`**，用 `string.char(...)`
8. 登记表键必须与函数名**同步改名**
9. `arrayWrapper` 必须定义在 `openFnArgs` **之前**

### 5.2 数组属性（用户纠正过两次）

```lua
-- 定义
tableIds = {
    type = Mini.Array,
    itemType = Mini.String,
    default = Mini.Array(Mini.String, "id1", "id2", ...),
    displayName = "二维表ID组",
    customDisplayName = "表ID",
}

-- 读取（运行时）
local arr = self.tableIds
for i = 1, #arr do local v = arr[i] end
```

- 实测：`#arr` 能取长度（15），`arr[1]` 是 **1-based**，`arr[0]` 为 nil，`ipairs` 可用
- **不要用逗号分割字符串** —— 用户明确说过"偏要用字符串分割"
- `arrayWrapper` **只用于开放函数返回数组**，属性 default 直接 `Mini.Array(...)`
- 加惰性初始化：每个开放函数开头 `if not SELFREF then SELFREF = self end`

### 5.3 二维表 playerId 语义 ★用户纠正

```
playerId = nil 或 0  →  全局房间变量（二维表存这儿）
playerId = 非0数字   →  私人个人变量
```

**读二维表一律传 nil 或 0。** 传任何非 0 数字都查的是私人变量，永远返回 nil。

正确写法（从用户能跑通的脚本抄的）：
```lua
Data.Table.GetAllValue(Data.Table, tid, nil)   -- 先试 nil
Data.Table.GetAllValue(Data.Table, tid, 0)     -- 再试 0
```

限制：500KB / 2000 行。**但实测 table 内存能到 ~100MB**（用户说的，未精确测定）。

### 5.4 self:ThreadWait ★用户纠正

**参数是【秒】，不是 tick。**

```lua
self:ThreadWait(0.01)   -- 等 0.01 秒
```

- 必须在**协程**里调用（`coroutine.create` + `resume`），裸调用报错
- 用途：分批/定时循环，让出帧，避免引擎判卡死
- 我一度默认设成 20（=20秒），300批要跑一个多小时。现在默认 **0.05**
- 取值建议：0.01~0.05 逐条播报，0.5+ 慢速演示
- 退化：探测 `type(self.ThreadWait)=="function"`，失败则同步跑完

```lua
local co = coroutine.create(function()
    for i = 1, 100 do
        doSomething(i)
        self:ThreadWait(0.05)
    end
end)
coroutine.resume(co)
```

### 5.5 引擎元数据：转储存在 ≠ 可用

- `loadstring` 转储里有，**实测返回 nil**（被 stub）
- `collectgarbage` 真机是**坏 stub**：`type()` 检测通过但调用报 nil
  → **不要用它测内存**，自己算：块数 × 每块大小
- `Mini` 只有 `Array` 一个显式字段，其余走元表 `__index`，转储抓不到
  → 但 `Mini.String.__className_ == "String"` 实测成立（50种无一例外）

**判断能否用，必须实测，不能只看转储清单。**

### 5.8 广播

# 拼音输入法 · 修复说明

## 原来的问题

脚本内置的二维表 ID 是 **17 个旧 ID**，和你新导入的 **19 个 ID 完全不同** →
一张表都读不到 → 字典载不进来 → 所有查询返回空串。

不是解码逻辑的问题：解码链路（Base85 → inflate → 变长解码）实测完全正确。

## 改动

1. **默认 ID 换成你给的 19 个**（按你给的顺序，对应表序号 1–19）
2. **头部注释 17 → 19**
3. **总表数解析**：scanAll 从 `M|表序号|总表数|本表行数` 读出总表数
4. **表头容错**：换表后若第 2 行不是 `C|` 分片，向后最多探测 10 行
   （应对 CSV 的「字段备注/字段名/字段类型」三行被一起导入成数据行的情况）
5. **Status 增强**：显示「读到 n 张 / 总表数 N」、段索引段数、最近加载失败原因；
   读到数 < 总表数时明确提示"数据未传完，超出部分的拼音查不到（数据缺失，非脚本故障）"
6. **清理冗余**：重复 bit 声明、未使用的 DLENS_ORDER、重复的 BIDX、重复的 _G.__DBG

## 当前状态：数据只传了 8/19 张

```
ni / wo / zhong -> 空
```

**这是数据缺失，不是脚本故障。** 现有 8 张表的段覆盖到字母序 `k` 附近
（最后一批块索引是 Ika / Ike / Iko），首字母模糊表 G 段也还没到。

补齐剩余 11 张表后这些拼音就能查到。导入后调 `Status()` 会显示
「读到 N 张 / 总表数 19」，N=19 就说明传全了。

## 用法

1. 导入 `拼音输入法_二维表版.lua` 作为组件
2. 属性 `tableIdsText` 已内置 19 个 ID，一般不用改
3. 触发器调 `Type("ba")` 拿候选，调 `Status()` 查运行状态

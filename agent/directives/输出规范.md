# 回复输出规范（末尾整洁）

> 主管签发 · 2026-10-09
> **所有对话必须遵守**，违反主管打回

## 问题背景

带文件的回复在转发到其他 App 时，底部的文件标记会以原始 JSON 露出，
形成一大坨乱码，**难看且打断阅读**。

更糟的是：同一组文件被重复输出几十次，转发后就是一整屏垃圾。

## 硬性规则

### 规则 1：一组文件只出一次

```
✗ 同一组 media_info 重复 20 次   ← 绝对禁止
✓ 全文只出现一次
```

**这是最常见的错误，每次回复前自查。**

### 规则 2：文件数量 ≤ 3

超过 3 个必须先打包成一个 zip：

```bash
zip -r 交付包.zip 目录/
```

只有图片/视频不受此限。

### 规则 3：描述简短

```
✗ "自包含任务书：正文 + 附录 A-D（引擎铁律/arrayWrapper/环境能力/资源获取）"
✓ "模组工程师任务书"
```

一句话，15 字以内最好。

### 规则 4：位置

放在**整段回复的最后**，不要插在中间打断行文。
（如果图片在解释某段话，可以就近放，但文件卡片一律放末尾。）

### 规则 5：要转发的，给纯文本版

用户明确说"要转发给别的 AI"时：

- 关键内容**直接写进正文**，不挂文件卡片
- 文件路径只给一行链接
- 不输出任何标记块

用户不说"转发"，才走正常文件卡片。

## 自检清单（每次回复前）

- [ ] 媒体标记只出了一组，没重复
- [ ] 文件 ≤ 3 个（多了已打包）
- [ ] 描述简短
- [ ] 块在末尾，不打断行文
- [ ] 用户要转发 → 已切纯文本版

## 反面案例（真实发生）

一次回复把同一组 3 个文件重复输出了 **20 次**，
用户转发后看到满屏 JSON。
—— 这是本次规范出台的直接原因。

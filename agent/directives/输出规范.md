# 回复输出规范（末尾整洁）

> 主管签发 · 2026-10-09
> **所有对话必须遵守**，违反主管打回

## 问题背景

带文件的回复在转发到其他 App 时，底部的文件标记会以原始 JSON 露出，
形成一大坨乱码，**难看且打断阅读**。

更糟的是：同一组文件被重复输出几十次，转发后就是一整屏垃圾。

## 硬性规则

### 规则 1：一组文件只出一次

```
✗ 同一组 media_info 重复 20 次   ← 绝对禁止
✓ 全文只出现一次
```

**这是最常见的错误，每次回复前自查。**

### 规则 2：文件数量 ≤ 3

超过 3 个必须先打包成一个 zip：

```bash
zip -r 交付包.zip 目录/
```

只有图片/视频不受此限。

### 规则 3：描述简短

```
✗ "自包含任务书：正文 + 附录 A-D（引擎铁律/arrayWrapper/环境能力/资源获取）"
✓ "模组工程师任务书"
```

一句话，15 字以内最好。

### 规则 4：位置

放在**整段回复的最后**，不要插在中间打断行文。
（如果图片在解释某段话，可以就近放，但文件卡片一律放末尾。）

### 规则 5：内容长就给文件，不要贴进正文 ⭐ 最重要

**用户明确偏好（2026-10-09）：「文本太多的给我文件就行了。」**

判定：正文超过约 40 行 / 或是一份完整文档（任务书、报告、长代码）→

```
✓ 写成文件，末尾给一个文件卡片
✗ 整篇贴进对话正文
```

理由：长正文刷屏、难复制、转发时格式全乱。

### 规则 6：转发场景

用户说"要转发给别的 AI"时，两个选项：

- **优先**：给文件，用户自己转发文件
- 用户坚持要能直接复制 → 才出纯文本版

**不要默认把长文贴进正文**——即使说了要转发，也先问一句或默认给文件。

## 自检清单（每次回复前）

- [ ] **内容超过 40 行 → 已写成文件，没贴正文** ⭐
- [ ] 媒体标记只出了一组，没重复
- [ ] 文件 ≤ 3 个（多了已打包）
- [ ] 描述简短
- [ ] 块在末尾，不打断行文
- [ ] 用户要转发 → 默认给文件，不默认贴正文

## 反面案例（真实发生）

1. 一次回复把同一组 3 个文件重复输出了 **20 次**，
   用户转发后看到满屏 JSON。→ 催生规则 1

2. 用户说"要转发"，我就把 269 行的任务书**整篇贴进正文**，
   用户回："文本太多的给我文件就行了。" → 催生规则 5

**教训**：给文件不等于偷懒，是对用户阅读体验负责。
长文贴正文 = 刷屏 = 用户更难用。

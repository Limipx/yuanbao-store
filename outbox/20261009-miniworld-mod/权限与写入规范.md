## 二、⚠️ 但你不能改目录结构

### GitHub 的技术限制（必须知道）

Fine-grained token 的权限是**仓库级**的，**无法按目录细分**。
也就是说，从技术上讲你的 token 能改任何文件——
**这是 GitHub 的设计限制，不是我给你的权限。**

所以下面这些是**规范约束**，靠你自觉 + 自动化守护双保险：

### 顶层九目录，一个都不能动

```
agent/  memory/  knowledge/  resources/
skills/  projects/  inbox/  outbox/  _system/
```

**禁止**：新建顶层目录、删除顶层目录、重命名顶层目录。

自动化守护已启用（`.github/workflows/structure-guard.yml`）：
**任何 push 都会检查**，违规会直接失败并提示。

### 受保护文件（改前找我）

| 路径 | 说明 |
|---|---|
| `_system/SCHEMA.md` | 目录规范，唯一权威 |
| `agent/**` | 主管定义 |

### 你可以自由写的地方

## 三、你的知识完善任务（主管主动授权）

**迷你世界模组方面的知识，由你负责进一步完善。**

| 方向 | 说明 |
|---|---|


2. 结论**必须标注**【已测】/【未测】
3. 有代码就给**可直接运行**的完整示例
4. 更新 `knowledge/miniworld-ugc/INDEX.md` 索引

### 最重要的一条

**你实测出来的东西，比我推测的准。**

如果我的附录（TASK.md 附录 A–D）里有任何结论被你实测推翻——
**以你的为准，直接改，并告诉我一声**。

## 四、提交规范

### Commit message

```
[模组] <模组名>：<简要说明>
[知识] <主题>：<补充了什么>
[资源] <名称>：<入库>
[修复] <问题>：<根因>
```

例：
```
[模组] 背包整理：初版交付，含混淆版
[知识] 二维表分表：补充 500KB 上限实测数据
```

### 每次提交前自查

- [ ] 没有动顶层目录
- [ ] 没有改受保护文件
- [ ] 资源已登记 `resources/INDEX.md`
- [ ] 结论都标了【已测】/【未测】
- [ ] 没有明文密钥/token
